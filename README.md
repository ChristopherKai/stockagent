# stockagent · 自选股研究系统

自动跟踪自选股的公告、新闻、行情和产业链，用带工具的 LLM agent 做研究，产出四类结果：

- **每日简报**：事件分级（重要性 1–5、方向、相对预期）、技术面、消息发布后的价格反应、论点跟踪；业绩发布后由代码算出「实际 vs 发布前一致预期」的差值。
- **深度报告**（Deep Dossier）：结构参照买方深度报告，包括现状、核心洞见、盈利驱动、资本与稀释、估值（可比公司、反向 DCF、敏感性矩阵）、12 个月情景、证伪条件和催化剂日历。
- **跟踪卡**：把报告里的证伪条件、催化剂、跟踪指标和产业链相关标的存成结构化数据，每天自动检查，触发时推送。
- **标的追踪**：以深度报告的估值矩阵为基线，每天按新事件增量修正估值假设，由代码重算目标价（情景加权估值），每次修正都写明改了什么、依据哪条事件；重大事件时自动排队重跑深度报告。
- **选股器**（`stock screen`）：从港股通与 A 股全市场里初筛出值得深研的标的（长线池、事件池；按「高胜率 + 高赔率 → 高胜率 → 高赔率」分层），由你点选送深研，接入上面的研究闭环。
- **模拟基金**（`stock fund`）：按市场设虚拟资金的模拟基金，每只跑一种策略、共用一套仓位与风控；盘前推送当日计划、盘中只推条件触发、盘后按规则模拟成交并记净值。明确标注的模拟组合，不对接券商、不下单。

另有本机 **WebUI**（`stock web`）：事件与修正时间线、观察清单增删改、开始 / 停止追踪、模型连接与任务路由、日程等配置都可在界面上完成，内置调度器按时运行。

系统辅助研究，**不构成投资建议**，也不会自动下单。目标价是按估值假设计算的情景加权估值，仅供研究参考。模拟基金的建议只是按规则生成的模拟组合信号，推送标题带「模拟基金」，正文附「模拟组合信号，非投资建议」。

## 工作方式：研究闭环

```
             ┌──────────────────────────────────────────────┐
             ▼                                              │
  数据层：行情 / 公告 / 新闻 / 年报 / 手动补充              │ 跟踪计划：产业链标的、
             │                                              │ 新闻关键词、待补数据
             ▼                                              │
  理解层：公司画像（读年报）→ 深度报告（agent + 工具）───────┘
             │
             ▼
  跟踪层：业绩对比一致预期（代码）→ 事件分级 → 证伪条件检查（价格类由代码判定、事件类由 LLM 判定）→ 标的追踪（修正估值假设）→ 简报 / 提醒
             │
             └─ 重大事件 / 论点失效 → 自动排队重跑深度报告 → 新的估值基线
```

数据采集不是只按公司名搜索：
- 深度报告读完年报、理解业务和产业链之后，会产出一份跟踪计划，写明要盯哪些上下游和同业公司、哪些产业链关键词、哪些行业指标。
- 数据层按这份计划扩大新闻检索和行情采集的范围。
- 自动采集不到的数据列为"待补充"，请使用者手动补充。

## 快速开始

```bash
uv sync                    # 安装依赖（Python 3.12，由 uv 管理）
uv run stock init          # 创建 .env、数据目录和收件箱
# 在 .env 填 key，在 config.yaml 的 llm 部分配置模型
uv run stock llm-test      # 逐个测试模型：连通、JSON 输出
uv run stock run --open    # 日常流程：导入 → 抓取 → 定期报告 → 画像 → 分级 → 证伪检查 → 简报
uv run stock dossier       # 深度报告（每家公司需要若干分钟，建议每周或财报后运行）
uv run stock target add 公司   # 开始追踪：用深度报告建立估值基线（代码计算，不调用模型）
uv run stock web --open    # WebUI（只监听 127.0.0.1）；内置调度器按日程运行日常流程
uv run stock track         # 查看论点、证伪条件状态、催化剂、跟踪计划
```

## 模型配置（不绑定任何一个模型）

`config.yaml` 的 `llm.profiles` 定义模型端点，`llm.tasks` 指定每个环节用哪个端点：

| 任务 | 作用 |
|---|---|
| `triage` | 事件分级 |
| `stock_brief` / `market_brief` | 个股研判 / 今日要点 |
| `profile` | 公司画像（读年报） |
| `research` | 深度报告的研究 agent（调用工具） |
| `dossier` | 深度报告撰写与跟踪卡 |
| `monitor` | 事件类证伪条件检查 |
| `tracker` | 标的追踪：修正 agent（带工具）与结构化修正 |
| `chat` | 报告研读对话：WebUI 报告页讲解深度报告（带工具） |

每个 profile 的关键参数：

| 参数 | 说明 |
|---|---|
| `protocol` | `openai`（OpenAI 兼容接口：本地网关、DeepSeek、通义、Ollama、vLLM 等）/ `anthropic`（Claude 官方 SDK）/ `mock`（离线演练） |
| `base_url` / `model` / `api_key_env` | 地址、模型名、存放 key 的环境变量（key 写在 `.env`） |
| `tool_mode` | `native`：用接口自带的工具调用；`text`：服务不支持时，用 `<tool_call>` 文本协议 |
| `json_mode` | 是否使用接口的 JSON 模式 |
| `max_input_chars` | 单次最多送入的资料字数；**不填 = 不限制**，只受 `report.profile_max_doc_chars` 控制 |
| `max_tokens` | 单次输出上限。文本输出达到上限时，会自动让模型从中断处续写，最多 `llm.max_continuations` 次；JSON 输出则用该上限重试一次 |
| `fallback` | 本模型不可用（连接失败、5xx、限流、上游拒绝）时自动改用的 profile；失败的模型 10 分钟内不再尝试 |

当前配置：
- 主模型：本地网关上的 `cn:deepseek-v4-flash`。
- 备用：`anthropic/deepseek/deepseek-v4.1-flash[1m]`。
- 备选：`qwen3.8-27b-splash`，没有被任何任务使用，需要时在 `tasks` 里改用即可。

每次调用的 token 用量都记录在数据库里，简报末尾有当日汇总。

## 研究 agent 的工具

| 工具 | 作用 |
|---|---|
| `calculate` | 安全计算器（Python 语法、多行赋值）；只允许数字运算和白名单函数，不能导入模块或访问属性 |
| `dcf_valuation` / `reverse_dcf` | 两阶段 DCF；当前市值隐含的增长率 |
| `valuation_matrix` | 敏感性矩阵：隐含股价 =（倍数 × 驱动指标 + 净现金）÷ 股本 × 汇率 |
| `list_filings` / `search_filings` / `read_filing` | 在已入库的年报、中报、研报、笔记中检索（兼容简繁体，带页码），并读取原文 |
| `market_data` | 任意标的行情与估值（自选股、港股 5 位数字、A 股 6 位数字、美股代码） |
| `financials` | 结构化主要财务指标，A 股和港股多期数据（东方财富数据中心）。港股的报告币种由数据推断（接口里的币种字段不可靠） |
| `statements` | 完整三张报表（利润表 / 资产负债表 / 现金流量表）：A 股、港股来自东方财富数据中心，美股来自 SEC XBRL（10-K / 10-Q / 20-F，需设置 `sec_user_agent`）。费用结构、减值、投资收益、有息负债各科目、折旧摊销、分红回购现金等明细；每列标明截止日与期间长度 |
| `shareholders` | 股东结构。A 股：十大股东（含进出与增减）、十大流通股东、股东户数与户均持股；港股：定期报告披露的主要股东与董事权益 |
| `ccass` | 港股中央结算系统（CCASS）持股：前 15 名参与者（托管行、券商、港股通）的持股与占比、较约 5 / 20 个交易日前的变化、前 5 / 前 10 名集中度、未存入 CCASS 的比例 |
| `broker_research` | 卖方一致预期。A 股：东方财富研报库的评级分布、未来三年 EPS/PE 预测中位数（每家机构取最新一篇）；港股：富途个股预测页的分析师数量与目标价均值/区间（经 Exa 读取）；美股：Nasdaq 的一致目标价、评级分布与年度 EPS 一致预期 |
| `earnings_vs_consensus` | 业绩 vs 一致预期（代码计算）：当前各年一致预期与近 30 / 90 天的修正趋势；近几个报告期「实际 vs 发布前一致预期」（年报看偏差，中报、季报看完成度并按近 3 年同期占比外推全年）。A 股按研报库回溯，港股用你录入的快照，美股另附 Nasdaq 季度业绩惊喜 |
| `fcf_yield` | EV 与自由现金流收益率（代码按现金流量表、资产负债表计算）：EV、FCF（TTM、近 3 个年度、3 年平均）、FCF Yield、净现金占市值、Negative EV、FCF 累计覆盖 EV 的年数、前瞻 FCF Yield；另给按总负债计算的保守口径 |
| `valuation_history` | 历史估值分位：当前 PE/PB 处于过去几年的什么位置。港股用日收盘价 ÷ 已披露 EPS，考虑披露滞后并做汇率换算 |
| `sotp` / `ddm` | 分部加总估值（上市子公司、多业务）；股息贴现 |
| `company_events` | 已分级的新闻与公告 |
| `manual_data` | 使用者手动补充的数据 |
| `ima_search` / `ima_read` | 在你订阅的 ima 知识库里按标题检索券商研报、调研纪要、付费新闻截图；读取原文时 PDF/Word 入库为本公司资料（之后用 `search_filings` 按页引用），图片返回 OCR 文字。只有配置了 ima 才提供（见下方「ima 知识库」） |
| `report_notes` | 检索深度报告正文、背后的研究笔记和写报告时的工具调用记录（只开放给报告研读对话） |
| `web_search` / `fetch_url` | 网页搜索（见下方「网页搜索」）；网页与 PDF 全文抓取。头条文章走移动端接口取正文；脚本渲染的网站（富途、雪球）、拒绝程序访问或正文太短的页面改用 Exa 读取；禁止访问本机和内网地址 |

规则写在提示词里：
- 数字必须来自工具，计算必须用工具，每条事实都要注明出处（年报页码、网页来源和日期）。
- 查不到就写"未披露"，不得编造。

报告附录"研究过程与出处"会列出每一次工具调用。撰写前，程序还会按最新行情重新计算 EV / 自由现金流并读取港股一致预期，作为「程序计算」的一节笔记交给撰写环节（复用旧笔记时也不会缺）。

agent 不能直接执行 shell 命令：研究 agent 会读大量不可信的网页，网页里的指令可能诱导它执行任意命令（读取 .env 里的 key、删除文件等）。外部能力一律做成固定的工具（程序和参数固定，参数只当数据传递）。

agent 参数在 `config.yaml` 的 `agent` 部分：最多几轮工具调用、单次工具结果的长度、搜索源、研究子任务是否并行。

## 深度报告与跟踪卡

`stock dossier [公司]` 的流程：
1. **研究**：4 个研究子 agent（业务与产业链、财务与资本、市场与估值、近期动态与风险）并行调用工具查证，写出研究笔记，完成后立即存盘。
2. **补缺检索**：从笔记中找出对多空判断最关键、但还没拿到的数据（如行业配额与价格、公司获配额度、卖方一致预期），由补缺 agent 换不同检索式专门搜索，并打开原文核实。仍找不到或只找到一部分（包括只有未经核实的来源）的，生成「需要你补充的数据」：已经有什么、还缺什么、为什么关键、从哪里获取、怎么补充。这些请求存入数据库，会在命令输出、简报和推送里提示；`stock requests` 可查看或关闭。
3. **撰写**：先从笔记中列出 12–20 条「必须覆盖的关键事实」（核心财务、分部、股权、资本运作、异常变化如应收票据激增），连同笔记和你补充的数据一起交给撰写环节。分两段撰写，只以这些材料为事实来源；笔记里已有的数据不得写成「未披露」。单段超出输出上限时，自动让模型从中断处续写。
4. **一致性核对**：把报告中所有「未披露/未查到」的说法逐条与研究笔记核对，笔记里其实有数据的，改写原句补上数据和出处。跟踪卡里的「待补充数据」也做同样核对。
5. **覆盖检查**：逐条检查关键事实是否写进了报告，遗漏的补一两句（带数字和出处）插入对应章节末尾。第 4、5 步的修改记录都附在报告附录。
6. 抽取跟踪卡（JSON，经过校验）：
   - 立场（偏多 / 中性 / 偏空）按 12 个月情景定义（见下方「立场怎么定」）；程序按情景区间与现价算出加权空间、跌破现价概率等数字，写进跟踪卡附录并与立场对账。
   - 证伪条件：每条标明方向——向下（情况比判断更差）或向上（情况比判断更好）；与立场相反的方向才是证伪（偏多被向下证伪、偏空被向上证伪、中性两个方向都会）。价格类的写明指标、上市地、阈值和动作（向下：复核 / 减仓 / 退出；向上：复核 / 上调判断），由代码每日判定；其余由 LLM 对照新事件判定，状态只升级不回退。
   - 催化剂日历（带可检验的 KPI）、跟踪指标、产业链相关标的、新闻跟踪词、待补充数据。
7. 数字溯源：检查报告中的数字能否在研究笔记或工具结果中找到对应（允许四舍五入和亿/万/千元换算），找不到出处的数字列在附录，提示人工核对。
8. 输出 `data/dossiers/<公司>_<时间>.html`（本机有 Chrome 时同时导出 PDF，使用独立的临时配置目录，不碰日常 Chrome）。跟踪计划写回数据库，下一次抓取即生效。

补充说明：
- 研究笔记完成后立即存盘（`data/dossiers/notes/`）。如果撰写阶段失败，运行 `stock dossier 公司 --reuse-notes` 可以跳过研究直接撰写；失败的研究子任务会单独重做。
- 数据请求的闭环：按报告附录「需要你补充的数据」补充数据（`stock data add`）或文件（`data/inbox/<公司>/`）后，运行 `stock dossier 公司 --reuse-notes`。程序发现上次补缺之后有新补充的数据，会带着上一轮的结果重新补缺，补充的数据也会直接交给撰写环节。新报告不再列出的旧请求（已查到或不再关键）自动标记为已解决。
- 重新生成报告时，上一版中已触发或出现苗头的证伪条件会交给新报告重新核实，不会被悄悄清零；旧记录保留在数据库里。
- 深度报告超过 `report.dossier_stale_days`（默认 30 天）时，简报会提示更新。

## 标的追踪（情景加权估值）

`stock target add 公司` 开始追踪；之后每次 `stock run`（或 `stock target run`）都会检查新依据并修正估值。

**估值基线（代码计算，不调用模型）**：深度报告里跟踪卡的情景价格区间，来自研究 agent 调用 `valuation_matrix` 算出的格点（隐含股价 =（倍数 × 驱动指标 + 净现金）÷ 股本 × 汇率）。程序从工具日志里找回能解释最多情景端点的那次调用（股本与行情对不上的调用会被跳过），为牛 / 基准 / 熊每个情景定出（驱动指标, 倍数）点，使代码算出的情景股价恰好等于卡片区间中值。同一价格常对应多个格点（高驱动 × 低倍数，或低驱动 × 高倍数），所以驱动指标优先取情景描述里写明的矩阵行（如「2027E 收入 1,000–1,100 亿」），否则牛市取命中格点里最大的、熊市取最小的，并保证 牛 ≥ 基准 ≥ 熊；调整过的写在基线标注里。找不到可用矩阵时退回「区间模型」（只能按比例修正情景价格）。情景价格按报告当时的定价上市地写成，跟踪卡会记下它，之后改了定价上市地也不会错位。

**目标价**：各情景股价按概率加权（`tracker.target: expected`，可改为 `base` 取基准情景）。汇率由代码按最新港元 / 美元兑离岸人民币日线计算。多地上市的公司另给其他上市地的等值价：主口径按两地现价之比折算（各上市地空间相同，已包含 AH / ADS 溢价），并附汇率平价（不计溢价）作参考。

**情景统计与立场怎么定**：程序按情景区间（区间内视为均匀分布）与现价算出四个数——加权空间、基准情景空间、跌破现价的概率、上行 / 下行比（上涨部分的期望幅度 ÷ 下跌部分的期望幅度），并按同一套定义给出「参考立场」：

| 立场 | 定义（`tracker.stance_band` 默认 15%） |
|---|---|
| 偏多 | 加权空间 ≥ +15%，且跌破现价的概率 < 50% |
| 偏空 | 加权空间 ≤ −15%，或基准情景低于现价且跌破现价的概率 > 50% |
| 中性 | 其余 |

立场仍由报告（与之后的修正）判断，程序不改写；与参考立场不一致时标 ⚠ 并说明，立场方向与加权空间正负相反时也附一句解释（例如偏空但加权空间为正，多半是牛市情景抬高了均值）。这些数字显示在公司页、修正页、简报和 `stock target show` 里，修正时也交给模型参考。注意：波动大的股票即使报告毫无看法，跌破现价的概率也常超过 50%，看到偏空时结合加权空间一起读。

**每次修正**：
1. 收集尚未处理的依据：报告之后分级的事件（重要性 ≥ `tracker.min_materiality`，按分级时间取窗口，补抓的旧新闻也不会漏）、升级的证伪条件、新入库资料、新补充的数据。没有依据时不调用模型。
2. 修正 agent 对照跟踪卡（论点、证伪条件、催化剂、跟踪指标）和报告的估值章节，打开事件原文核实、用工具量化影响；工具有白名单，网页搜索在深度报告运行期间自动暂停。
3. 结构化修正：模型只给出「改哪个假设（驱动 / 倍数 / 情景概率 / 股本 / 净现金）、set / add / mul 与操作数、理由、依据编号」，新值与目标价由代码计算。
4. 代码校验后应用：没有引用本次依据的、取值越界的、事实类数字（股本、净现金、直接设定的驱动）在所引依据和工具结果里找不到出处的，一律不采纳；**股本、净现金单次变动超过 25% 的不自动采纳**（可能是口径变化而不是新信息），列为「待你确认」，在 WebUI 里一键采纳。估值口径问题、报告内部不一致由模型单列，交给你决定。
5. 每条修正记录保存：原值 → 新值、理由、依据链接、评估过的全部事件、修正研究笔记与工具调用；找不到出处的数字另列提示核对。

**论点状态**：「论点」指深度报告的核心判断（跟踪卡上的核心论点与立场：偏多 / 中性 / 偏空），与公司基本面好坏无关。每次修正给出四种状态之一：

| 状态 | 含义 |
|---|---|
| 论点完好 | 新依据对报告的判断没有实质影响 |
| 论点加强 | 新依据支持报告的判断。报告偏空时，新的利空也属于加强 |
| 论点削弱 | 新依据与报告的判断相左，但还不足以推翻 |
| 论点失效 | 证伪方向的条件触发（偏多遇向下、偏空遇向上、中性任一方向），或核心前提被推翻；会自动排队重跑深度报告。与立场同向的条件触发（如偏空公司「交付不及预期」）属于印证，算加强 |

**重大事件**：重要性 5 的事件被修正判为实质影响，或论点被判失效时，自动排队重跑该公司的深度报告（冷却期 `tracker.redo_cooldown_days`，由 `stock web` 的任务执行器在没有其他深度报告运行时执行）；新报告完成后自动重建估值基线。上一版以来的修正记录会交给新报告的研究与撰写环节核实。

| 命令 | 作用 |
|---|---|
| `stock target add 公司 [--dossier]` | 开始追踪（没有深度报告时加 `--dossier` 先生成） |
| `stock target list` / `show 公司` | 追踪状态与目标价 / 当前估值模型与修正记录 |
| `stock target run [公司] [--no-fetch] [--push]` | 抓取、分级后按新依据修正（`stock run` 已包含这一步） |
| `stock target rebase 公司` / `remove 公司` | 用最新深度报告重建基线 / 停止追踪（历史保留） |

## 业绩 vs 一致预期

每次 `stock run`（抓取之后、分级之前）检查新发布的业绩，与**发布前**的一致预期对比，全部由代码计算：

| 市场 | 一致预期从哪来 | 实际值 |
|---|---|---|
| A 股（A+H 公司按 A 股口径、人民币） | 东方财富研报库按发布日还原：发布前 120 天内每家机构取最新一篇，EPS 取中位数；研报库收录太少（少于 3 家）时改用发布前的机构预测汇总快照 | 定期报告（带公告日）、业绩预告（归母净利区间，按股本换成 EPS）、业绩快报 |
| 港股 | 没有免费的盈利预测，**由你录入**：公司页「业绩 vs 一致预期」卡片或 `stock consensus set`。程序取业绩发布日之前最近的一份，币种不同时按发布日汇率换算 | 东方财富港股财务指标；发布日取 [中期業績] / [末期業績] / [季度業績] 公告的时间（一个月后刊发的中期报告全文不算） |
| 美股 | Nasdaq 年度 EPS 一致预期每天存一份快照；中概股 ADS 口径按 `ads_ratio` 换成每股 | 港美两地上市的用港股报表 |

怎么比：年报看偏差（实际 ÷ 一致预期 − 1）；中报、季报是年初至今累计，看完成全年一致预期的比例，并按近 3 年同期占比外推全年。一致预期为亏损或接近零时只给差额。样本少、一致预期过时、历史同期占比波动大、口径不同（Nasdaq 多为经调整 EPS）都会标注。

结果生成一条「一致预期对比」条目（摘要以 `[程序计算]` 开头）进入分级：分级模型据此写「相对预期」并按偏离幅度定重要性，之后与其他事件一样进入证伪条件检查、标的追踪和简报。第一次检查某家公司时只对比 10 天内发布的业绩（`consensus.lookback_days`）。港股业绩发布时还没有录入一致预期的，会提示补录（把日期填成发布前的日期），30 天内补录都会自动对比；港股业绩期内 90 天没有录入的，简报的「数据缺口」会提醒。

| 命令 | 作用 |
|---|---|
| `stock consensus show [公司]` | 当前一致预期、近 30 / 90 天修正趋势、历史各期实际 vs 发布前一致预期 |
| `stock consensus set 公司 财年 --eps X --currency CNY [--n 家数] [--source 富途] [--date YYYY-MM-DD]` | 录入一致预期（也可 `--profit` / `--revenue`，单位亿） |
| `stock consensus check [公司]` | 记录快照、检查新业绩（`stock run` 已包含这一步） |

## 多地上市：定价上市地与 ADS

- **定价上市地**：情景价格、目标价和价格类证伪条件按哪个上市地计算。观察清单里可以给公司写 `pricing: HK`（或 A / US），不写时港股优先、其次 A 股、美股——A+H 公司和港美两地上市的公司都以港股定价。改动从下一份深度报告起生效（旧报告的情景价格仍按当时的上市地解读）。
- **ADS 换股比例**：美股上市地写 `ads_ratio`（1 份 ADS 对应的普通股数，如小鹏 XPEV 为 2）。用于计算美股 ADS 相对港股的溢价（与 AH 溢价一起显示在行情、报告头部与 `market_data`），以及等值价的汇率平价。
- **EV 与 FCF Yield**：报表仍用 A 股（A+H 公司），市值按定价上市地的股价；其他上市地的股价下的 EV 与 FCF Yield 另列一行（AH 溢价大时两者差别很大）。
- 观察清单表单里有「定价上市地」和「ADS 换股比例」两个字段。

## 选股器（stock screen）

目标按优先级：**① 高胜率 + 高赔率 → ② 高胜率 → ③ 高赔率**。用漏斗把全市场缩到每天几家值得花几分钟深研的公司。输出是研究候选，不是买卖建议。

```
L0 股票池：港股通（约 660 只）+ A 股（约 5500 只）。东方财富数据中心批量接口，报表、分红、解禁、预约披露都按期缓存
L1 硬过滤：市值、ST、上市满一年
L2 代码打分：五个策略桶 + 粗算赔率 + 前瞻催化剂 + 价值陷阱标记 → 分层（全部由代码计算）
   └ 候选再核对流动性（20 日成交额中位数、停牌天数）
L3 模型快筛：每家一次结构化判断（为什么便宜、陷阱风险、催化剂、深研要核实的问题）；只能淘汰，不能升级
L4 深研：你在 WebUI 点「送深研」→ 写入观察清单 → 新公司初始化（深度报告 + 开始追踪）
L5 事后检验：记下入选价格，按池 / 分层 / 策略桶统计之后的超额收益与胜率（stock screen eval）
```

### 策略：五个策略桶、两个池

| 策略桶 | 入选条件（代码判断） | 主要贡献 | 所在池 |
|---|---|---|---|
| 现金地板 | Negative EV，或净现金 ≥ 市值 50%，或保守 FCF Yield ≥ 8% 且近 3 年至少 2 年 FCF 为正 | 胜率（下行有地板）+ 赔率 | 长线池 |
| 质量红利 | 近 3 个年度与 TTM 的 FCF 全为正且稳定（最差年度 ≥ 3 年平均 × 40%）；连续派息 ≥ 3 年；股息率 ≥ 4% 且被 FCF 覆盖；保守 FCF Yield ≥ 5%；净负债 ≤ 市值 50%；利润同比不低于 −20%；没有严重风险标记 | **胜率**（收益主要来自确定的现金回报，不靠估值修复） | 长线池 |
| 产业链瓶颈 | 在 `themes.yaml` 你维护的主题节点里；瓶颈节点加权，看收入增速、毛利率同比、估值约束（FCF Yield ≥ 3% 或 PE ≤ 40） | 赔率（上行凸性） | 长线池 |
| 事件催化 | 近 30 天正面公告强度 ≥ 1（私有化 / 要约 3、特别股息 2、分拆 2、增持 1.5、资产出售 1.5、回购 1、重组 1、股权激励 0.8，按 15 天半衰期衰减，回购最多记 1.5），且没有否决事件 | 胜率（时点） | 事件池 |
| 预期修正 | A 股业绩预告（预增 / 扭亏，按增幅加权）或港股正面盈利预告；或最新一期（200 天内）归母净利同比 ≥ 30% 且收入同比 ≥ 10%；近期没有预减 / 盈利警告 | 胜率（趋势） | 事件池 |

- **长线池**（6–24 个月，每周六运行）：现金地板、质量红利、产业链瓶颈。
- **事件池**（1–3 个月，每个交易日 18:00 运行）：事件催化、预期修正，另要求估值有安全垫（保守 FCF Yield ≥ 3% 或 PE 在 0–40 倍，且没有严重风险标记）。
- 否决事件（任一出现即不进事件池、分层降为 D）：非标审计 / 更换核数师、立案调查 / 处罚、违约 / 清盘、退市风险 / 延迟披露、盈利警告、业绩预减 / 亏损。供股配售、股东减持为一般风险标记。
- 新闻不单独作为选股信号，只通过公告事件起作用。

### 赔率怎么算（粗算，只用于排序和分层）

```
保守 FCF   = min(TTM FCF, 近 3 年平均 FCF)            FCF = 经营现金流 − 资本开支
合理价值   = 保守 FCF ÷ 8% + 净现金                   （FCF 不为正时只算净现金 × 70%）
地板       = max(净现金 × 70% + 最差一期 FCF ÷ 20%, 0)  （净负债全额扣减，不打折）
上行       = 合理价值 ÷ 市值 − 1
下行       = max(1 − 地板 ÷ 市值, 15%)                 （地板高于现价时也按 15% 市场风险计）
赔率       = 上行 ÷ 下行（上限 20）
```

- 净现金 = 现金及短期投资 − 有息负债；EV = 市值 + 有息负债 + 少数股东权益 − 现金及短期投资（与深度报告的 `fcf_yield` 工具同一口径）。港股以人民币报账的按港元兑人民币汇率换算市值。
- 用「最差一期 FCF」算地板，周期股（汽车、资源）的下行因此明显更大；净现金打七折是因为现金可能滞留在子公司、不分配。
- EV 不到市值 10% 时 FCF Yield 没有意义（分母接近 0），按「EV 接近零」处理。
- 只因产业链主题入选的成长型公司不算粗算赔率（按当前 FCF 会严重低估），赔率留给深度报告的情景估值。
- 参数都在 `config.yaml` 的 `screen`：`fair_fcf_yield`、`bear_fcf_yield`、`cash_haircut`、`min_downside`。

### 胜率怎么判断

不用模型给的概率（未校准）。筛选阶段用三类可观察的证据作代理，上线后用 `stock screen eval` 的实测命中率逐步校准：

1. **下行有地板**：粗算下行 ≤ 20%（净现金厚、现金流稳定）。
2. **有催化剂**：代码能识别的催化剂（见下节），让价值有兑现路径。
3. **现金流稳定、有现金回报**：质量红利桶的全部检查通过。

再用价值陷阱标记排除「便宜有理由」的公司：FCF 不稳定、TTM FCF 为负、存贷双高（严重）、净现金高但不派息（港股）、少数股东权益超过市值一半、净负债超过市值、报表过旧、A 股 60 天内大额解禁（严重）、近 20 日 3 天以上无成交（停牌，严重）。港股标准化报表里资本开支科目缺失时，按投资活动净流出估算并标注。

### 「分」是怎么打的（只用于排序）

分数决定两件事：每个策略桶按分数取前 40 名进入候选（`top_n`），同一分层内按分数排序。**分层不看分数**，看上面的胜率与赔率条件。各项权重是按投资逻辑设定的经验值，没有用历史数据拟合，要靠 `stock screen eval` 的结果调整。

| 策略桶 | 得分（满分约 100） |
|---|---|
| 现金地板 | 40 × min(保守 FCF Yield ÷ 25%, 1) + 25 × min(净现金 / 市值, 1) + 10 × FCF 为正年数 ÷ 3 + 10 × min(股息率 ÷ 8%, 1) + 15 × min(赔率 ÷ 5, 1) − 10 × 严重风险标记数 − 4 × 一般风险标记数；Negative EV 另加 10，EV 接近零加 5 |
| 质量红利 | 30 × FCF 稳定度（最差年度 ÷ 3 年平均，最多 1）+ 25 × min(股息率 ÷ 7%, 1) + 20 × min(保守 FCF Yield ÷ 12%, 1) + 15 × min(连续派息年数 ÷ 5, 1) + 10（净现金为正） |
| 事件催化 | 60 × min(事件强度 ÷ 4, 1) + 20（估值有支撑：保守 FCF Yield ≥ 5% 或 PE 0–15 倍）+ 20（没有负面事件） |
| 预期修正 | 30 × min(净利同比 ÷ 100%, 1) + 20 × min(收入同比 ÷ 40%, 1) + 15 × min(毛利率同比 ÷ 5 个百分点, 1)（这三项只看 200 天内的报告期）+ 35 × min(业绩预告权重 ÷ 2, 1) |
| 产业链瓶颈 | 35（瓶颈节点）+ 20 × min(收入同比 ÷ 40%, 1) + 20 × min(毛利率同比 ÷ 5 个百分点, 1) + 25 × 估值约束（保守 FCF Yield ≥ 3% 或 PE 0–40 倍记 1，PE > 80 或亏损记 0，其余 0.5） |

候选在池里的总分：
- 长线池 = 所在各桶的最高分 + 10 × min(事件强度 ÷ 2, 1) + 5 × min(催化剂个数, 2) − 15（有否决事件）
- 事件池 = 所在各桶的最高分 + 10（估值有安全垫，否则 −10）+ 5（强催化：事件强度 ≥ 2 或业绩预告权重 ≥ 1.5）

所以总分可能超过 100。WebUI 上把鼠标停在分数上，可以看到各桶的得分。

### 分层

| 分层 | 条件（两个池相同，事件池 A 类赔率门槛为 2） |
|---|---|
| **A 高胜率 + 高赔率** | 赔率 ≥ 3、下行 ≤ 20%、有催化剂、没有严重风险标记（事件池另要求估值有安全垫） |
| **B 高胜率** | 质量红利入选，或「有催化剂 + 下行 ≤ 20%」；赔率 ≥ 1；没有严重风险标记 |
| **C 高赔率** | 赔率 ≥ 3（或产业链瓶颈评分 ≥ 50 的成长型），但胜率证据不足 |
| **D 观察** | 其余；有否决事件的一律为 D |
| X 快筛淘汰 | 模型快筛判为明显陷阱（模型只能淘汰，不能升级） |

### 催化剂：已发生的公告 + 前瞻日历

只看已发生的公告确实太单薄，所以催化剂分三个来源，都在池的时间窗内计算（长线池 365 天、事件池 90 天）：

1. **近期公告**（已发生，30 天内）：上面事件催化桶里的正面公告。
2. **前瞻日历**（代码按结构化数据推算未来事件）：
   - 已公告、尚未除息的派息；A 股已公告的分配预案（确定）。
   - 按往年同期除息日推算的下一次派息：要求连续派息 ≥ 3 年，且股息率 ≥ 4%（标〔推算〕）。
   - 业绩窗口：A 股定期报告预约披露日；港股按财年推算的法定披露期限（中期报告期末后 2 个月、年度 3 个月）。只有业绩趋势向上（预期修正桶入选）时才算正面催化剂。
   - A 股限售解禁（负面）：未来 120 天解禁占总股本 ≥ 3% 或占流通股 ≥ 5% 的列为风险；60 天内且占总股本 ≥ 10% 或流通股 ≥ 20% 为严重风险。
3. **深度报告核实过的催化剂**：观察清单里已有深度报告的公司，报告里带具体日期的催化剂直接纳入（研究 agent 用工具查证过）。

**为什么不让模型预测催化剂参与分层**：实测中，模型会在没有任何公告依据时「推测」出分红或回购，据此把 B 升为 A。所以模型在快筛里列出的催化剂只展示、标明是否推测，不参与分层；要确认的未来事件交给深度报告去查证，查证过的再通过第 3 类回到选股器。还没接入、以后可以加的前瞻事件：恒指 / 港股通季度调整的纳入预测、私有化与要约的时间表、回购计划的剩余额度。

### 流动性怎么评估

- 在代码打分之后、模型快筛之前，对候选逐只取近 20 个交易日的日线。
- **过滤**：20 日成交额中位数低于下限的剔除（港股 1000 万港元、A 股 3000 万元，`min_avg_amount`）。用中位数而不是均值，避免一两天放量把流动性差的股票放进来。
- **停牌**：20 日内 3 天以上没有成交，标为严重风险，A / B 类降为 D。
- **可容纳资金**（参考，不参与过滤）：成交额中位数 × 10% 参与率 × 5 个交易日（`participation`），在页面上显示。
- 成交额的来源依次是：日线成交额（东方财富）→ 换手率 × 市值 → 成交量 × 收盘价（腾讯备用源的 A 股只有成交量，单位是手 = 100 股）。取不到日线的不剔除，标「流动性未核对」。

### 用法

```bash
uv run stock screen run                  # 刷新数据（首次下载全市场报表与分红约 3 分钟）→ 两个池打分 → 模型快筛
uv run stock screen run --event-only --no-llm   # 只跑事件池、不调用模型
uv run stock screen show --tier A,B,C,D  # 最近一次的候选（默认 A,B,C）
uv run stock screen promote HK:00700     # 送深研：加入观察清单（之后运行新公司初始化）
uv run stock screen themes [--suggest]   # 查看主题与节点 / 运行主题 agent（每月 1 日自动运行）
uv run stock screen eval                 # 事后检验
```

WebUI 的「选股」页：两个池分页，按 A–D 分组显示指标、流动性、分红记录、催化剂（含前瞻日历）、风险标记、快筛结论与公告；「送深研」一键写入观察清单并提交新公司初始化；主题 agent 的建议在这里采纳或忽略（采纳后才写进 `themes.yaml`）。`stock screen run --push` 推送 A、B 类候选。

注意：全市场数据全部走数据中心接口（`datacenter.eastmoney.com`），不用行情列表接口——后者批量翻页会被限流，连带单只行情快照也会失败。

## 模拟基金（stock fund）

按市场设模拟基金（虚拟资金，默认每只 100 万本币），**一只基金只跑一种策略**，所有基金共用一套仓位与风控引擎。策略只给「选什么、目标权重、止损、理由」，买多少、何时降仓由风控统一决定；成交按规则模拟，逐日记净值。**这是模拟组合信号，非投资建议**：不对接券商、不下单，推送标题都带「模拟基金」。基金定义写在 `funds.yaml`（与 `config.yaml` 同目录），修改后运行 `stock fund sync`。

第一期两只基金：

| 基金 | 股票池 | 选 | 买 | 卖 | 仓位 |
|---|---|---|---|---|---|
| 港股质量价值（上限 15 只，季度调仓） | 全部港股通（选股器的全市场表） | ROE、负债率、近 3 年 FCF、毛利率稳定性过滤后，按「质量 + 便宜」综合排名（格林布拉特式；便宜 = 盈利收益率与保守 FCF Yield，在整个股票池里排名） | 有情景加权目标价的：现价 ≤ 目标价 × 0.75；没有的：便宜程度排前 20%。分 3 批，回调或下个调仓日补齐 | 证伪条件触发（exit 清仓、reduce 减半）；现价 ≥ 目标价（或合理价值）× 1.2 止盈；调仓日质量条件不再满足。不设机械止损，较成本跌 20% 推送复核 | 按综合得分 5%–15% |
| A 股景气趋势（上限 10 只，每周调仓、每天检查） | 全部 A 股：先用批量数据（市值、ST、退市）筛到前 1200 只，再用日线 | 收盘 > 50 日线 > 150 日线 > 200 日线、200 日线上行、距 52 周高点 25% 内、相对强度前 20%、行业动量前 40% | 放量（量比 ≥ 1.5）突破之前 20 日最高价；先买一半，站稳且浮盈再买另一半，只加盈利的仓位 | 硬止损 7.5% 或 2 倍 ATR（取近者）；浮盈 10% 后移动止损；跌破 50 日线减半；3 周不涨时间止损 | 每笔风险 = 净值 1% ÷ 止损距离 |

**共用风控**（所有基金一样，多个上限同时生效取最小）：

- 市场状态（每个市场每天一次）：指数是否在 200 日线上、宽度（日线股票池中站上 50 日线的比例）、20 日波动率分位 → 进攻 / 中性 / 防守。总仓位上限：趋势基金 100% / 60% / 30%（防守不开新仓，中性只开最强的一笔），价值基金 100% / 85% / 60%。
- 单票 15%、同一行业 30%、最小仓位 3%（计划满仓权重不到 3% 的不开）、流动性（选股器同一口径的容量：20 日成交额中位数 × 10% × 5 天）、同一发行人在全部基金合计不超过总资金 10%（A+H 合并）。
- 回撤熔断（按单位净值从最高点）：5% 新开仓减半（回撤收窄到 3% 内解除），10% 停止开新仓、总仓位降到 50% 以下（5% 内降档），15% 基金暂停，只处理退出，`stock fund resume <基金>` 手动恢复。
- 权重偏离不到 5 个百分点不调；满仓时新候选得分须比最弱持仓高 20% 才替换（只在调仓日）；按交易单位取整（A 股 100 股、科创板起买 200 股；港股按每手股数，查不到时按 100 股并在推送里标出）；先卖后买。

**防价值陷阱**（港股质量价值，新建仓前三道闸，只会去掉候选，不会增加或调整仓位）：

- 极端值按上限计分并在理由里标出：ROE 40%、盈利收益率 20%、FCF Yield 20%（`roe_cap` 等）；FCF 须在最近 3 个年度至少 2 年为正（年度数据不足的不达标），且最差一年不低于平均的 30%（排除营运资金一次性波动撑起来的高 FCF）；选股器的风险标记（不派息的现金堆、少数股东权益过大、净负债、报表过旧等）直接排除。
- 风险排除（所有基金共用）：`funds.yaml` 的 `exclusions` 里维护的名单（代码、名称关键词，例如控股股东清盘的公司），加上选股器全市场公告扫描（`screen_events`）近一年的负面事件（清盘 / 违约 / 债务重组、退市风险、非标审计、立案调查；覆盖范围从选股器开始扫描那天算起）。已持有的标的命中时按「论点失效」卖出。
- 模型否决：计划里的每笔新建仓先交给模型（与选股器快筛同一个模型路由，不带工具）回答「放行 / 否决 + 一句理由」，被否决的由后面的候选递补；结果按「标的 + 最新报告期」缓存，晚间刷新时预先检查。模型不可用时新建仓一律跳过（宁可不买）。否决与排除的数量和前几只写在计划的「提示」里。

**模拟成交**：盘前建议按当天开盘价成交，条件单按触发价成交（突破买单还要全天量比达标；跳空按开盘价），扣佣金、印花税、规费与滑点（`funds.yaml` 的 `costs`，港股印花税与规费按港交所收费页核对过；佣金、滑点按自己的券商改）。A 股一字涨停买不到、一字跌停卖不出。行情是前复权日线，股息没有记入现金，除权除息后的净值偏保守。

**节奏与数据**：

```
晚间  stock fund refresh   指数、汇率，及两个市场第一阶段股票池（港股前 400、A 股前 1200）+ 持仓的日线。
                           逐只限速请求（默认 1 秒一只），东方财富断开时自动切到腾讯，连续失败 8 只就停，下次从最旧的接着做。
```

港股、A 股休市日（`fund/calendar.py`：港股按香港政府公布的公众假期，A 股按交易所休市通知；A 股 2027 年的安排交易所还没发布，录入前按周一至周五处理并在计划里提示）不出计划、不结算；只有一个市场休市时只处理开市的那个。每个命令都有 `--dry-run`：不写库、不推送，只打印。`stock fund status` 查看净值、持仓、待执行建议与最近打分。

## WebUI（stock web）

`uv run stock web --open` 启动本机界面（默认 http://127.0.0.1:8765，只监听本机）：

- **仪表盘**：追踪标的的现价、目标价、空间、论点状态与最近修正；最新修正流；证伪条件苗头；近期催化剂；待补充数据；任务与日程。
- **标的页面**：走势图（收盘价、目标价阶梯线、牛熊区间、事件节点与修正节点，点击跳到时间线）、当前估值模型（与基线对比）、事件与修正的时间线、证伪条件、催化剂、待确认的修改；可立即检查、重建基线、重跑深度报告，录入消息、补充数据、上传文档。
- **深度报告（当前版本）**：原报告不改动，修正记录与最新估值表附在前面。
- **修正详情**：
  - 从上到下依次是：结论与目标价、需要你留意的问题、假设变化、修正后的估值模型（与上次对比）、未采纳的修改、修正研究笔记、本次评估的依据、工具调用。
  - 依据的排序：实质影响在前，然后是轻微、未评估，同一档内按重要性从高到低；不影响估值的依据折叠在最后。
  - 假设变化里的依据编号可以点击，直接跳到对应的依据或工具调用。
- **研读对话**（深度报告页与修正详情页的右侧栏；修正页的对话围绕这次修正）：读报告时遇到看不懂的术语、数字或推理，可以直接提问；在正文里选中一段文字，点「问这段」即可引用。详见下方「报告研读对话」。
- **观察清单**：填股票名称或代码（腾讯控股、2577、300308、XPEV；市场可选，默认自动识别）就能「一键添加并初始化」：名称用东方财富搜索联想识别成代码（只认正股，剔除窝轮、ETF、ADR 等；匹配到几家不同公司时会列出候选，请输入完整名称或代码），后台任务从东方财富公司概况查名称、英文名、繁体别名、行业、主营，以及同一家公司的其他上市地（A+H、港股+美股，按东方财富的机构代码关联），写入观察清单后依次抓取 → 年报 → 分级 → 画像 → 深度报告 → 开始追踪。也可以手动填写完整表单；增删改都写回 `watchlist.yaml`（保留注释，股票代码加引号防止被当成数字）；支持批量开始 / 停止追踪。命令行等价于 `stock add 腾讯控股 --onboard` 或 `stock add HK 2577 --onboard`（`--dry-run` 只查询不写入）。
- **设置**：LLM 端点（profile）的增删改、key（写入 `.env`，页面只显示掩码）、获取模型列表、连接测试、任务路由；日程；标的追踪与数据源等参数；密钥；直接编辑原始配置。所有修改写前完整校验，原文件备份到 `data/backups/`。
- **任务**：抓取、分级、深度报告、修正等耗时操作在后台子进程运行，日志实时显示，可取消。只能运行登记过的命令（固定参数，不经过 shell）；深度报告同一时间只跑一个。

安全：只监听 127.0.0.1，校验 Host（防 DNS rebinding）；所有修改操作校验 Origin 与 CSRF token（防止其他网页借浏览器改掉模型地址、把 key 发出去）；报告与修正说明里的 HTML 一律净化。

## 报告研读对话

深度报告页和修正详情页右侧的对话栏，帮助读懂报告和修正。在修正页提问时，模型还会拿到这次修正的全部记录：结论、假设变化、未采纳的修改、依据评估、研究笔记和工具结果。引用修正记录用【修正 #N】，也会逐字核对原文。它的角色是**讲解员，不是第二个分析师**：讲清报告写了什么、为什么这样写，不改变报告的结论、情景、概率或目标价，也不给买卖建议。

防止讲偏原报告的做法：
- **标注来源**：回答里的论断按来源标注：
  - 【报告·章节】：「」里是逐字引文；
  - 【研究笔记】：写报告时的原始推理与出处；
  - 【资料】：年报、财务数据、行情；
  - 【网页·来源 日期】：报告之外的新信息；
  - 【解释】：通用概念，或模型自己的推断。
- **不替报告编理由**：问「报告为什么这样判断」时，先查研究笔记（`report_notes` 工具）；报告没展开的就直说「报告未展开说明」。
- **不改结论**：
  - 问题的前提与报告不符时，先指出报告实际怎么写。
  - 网上的新信息或你的看法与报告不同时，只并列双方依据，不下结论。
  - 报告结论要更新，走标的追踪的修正或重跑深度报告。
- **代码核对**（不调用模型）：
  - 【报告】引文逐字对照原文。找得到的可以点击，跳到正文对应段落并高亮；找不到的标「⚠ 可能是转述」。
  - 回答中的数字对照报告、研究笔记、修正记录和本次工具结果溯源，找不到出处的列出来请你核对。
  - 这是启发式检查，推理本身对不对，仍要你对照原文判断。
- **不回流**：对话只保存在本机数据库里，供以后回看，不会成为估值修正或下一份深度报告的依据。

对话能用本地资料工具：报告与笔记检索、年报检索、财务、行情、估值历史、计算器。

界面：
- **流式输出**：回答边生成边显示。
- **回答过程**：模型的思考、每一次工具调用（参数与返回结果），以及中间说明，按顺序显示在答案上方。回答时自动展开，回答完成后折叠，历史对话里也能展开回看。
- **联网搜索开关**：输入框下方的「联网搜索」只影响这一次提问（网页搜索与打开网页）；默认值取 `chat.web_search`，浏览器会记住你上次的选择。深度报告运行期间，联网搜索一律自动暂停。
- **全屏**：点对话栏右上角的 ⤢ 全屏阅读，Esc 退出。

回答在 `stock web` 进程的后台线程里生成，页面通过 SSE 实时接收。服务重启时，没写完的回答会标为中断。

参数在 `config.yaml` 的 `chat` 部分（也可以在「设置 → 通用」里改）：`web_search`、每次回答最多几轮工具调用 `max_steps`、追问时带上多少轮历史 `max_turns`。模型由 `llm.tasks.chat` 指定。

## 事件重要性如何评估

每条新闻、公告、手动录入的消息都由分级模型（任务 `triage`）逐条判断相关性、类型、方向、是否新信息、相对预期和重要性（1–5）。

**模型看到的材料**：条目的标题、摘要、来源与发布时间；公司背景（画像、深度报告的论点与证伪条件、重点跟踪项）；当前行情；近 3 天已分级的事件（用于识别同一事件的多次报道）。

**评分标准**（写在 `triage.py` 的提示词里）：

| 分值 | 标准 | 例子 |
|---|---|---|
| 5 | 可能改变投资逻辑，或引发 10% 以上的波动 | 业绩大幅超预期或盈利警告、大客户得失、大比例折价配售、重大诉讼结果、纳入或剔除港股通 / 重要指数、重大处罚 |
| 4 | 显著影响，可能引发 5–10% 的波动 | 重要订单、业绩指引变化、大股东增减持、临近解禁、关键产品或认证突破 |
| 3 | 值得跟踪 | 产能进展、行业政策、竞争对手或上下游的重要变化、带新信息的研报 |
| 2 | 次要信息 | — |
| 1 | 噪音或例行公告 | 章程修订、会议通知等 |

**附加规则**：只报道涨跌或资金流、没有新基本面信息的，一般不超过 2；公司只是被顺带提及的标为不相关；同一事件的多条报道只保留一条，其余标为重复；定期报告只有标题、看不到数字的按 3 处理并注明要核对原文。交给模型之前，代码先做一次保守的标题去重。

**各环节的门槛**：

| 环节 | 门槛 |
|---|---|
| 简报 | 显示重要性 ≥ 2（`report.min_materiality`） |
| 证伪条件检查 | ≥ 3 |
| 标的追踪 | ≥ 3 的事件才进入修正（`tracker.min_materiality`） |
| 盘中推送 | ≥ 4（`notify.alert_min_materiality`） |
| 自动重跑深度报告 | = 5，且修正时判为「实质影响」（`tracker.redo_materiality`） |

重要性是模型对每条信息的一次性判断，会有误差；「事后检验」按事件发布后的实际超额收益，统计各档位的判断到底准不准。

## 后台任务说明

WebUI「任务」页和内置日程能运行的任务如下（与命令行一一对应）。平时不需要手动提交：日程定时运行「日常流程」，其中已包含标的追踪；临时检查某家公司，点标的页面的「立即检查」即可。

**常用**

| 任务 | 做什么 |
|---|---|
| 日常流程（`run`） | 导入收件箱 → 抓取行情、公告、新闻 → 检查定期报告 → 分级 → 证伪检查 → 标的追踪（修正估值）→ 生成简报；加 `--push` 推送日报 |

## 推送内容

在 `.env` 配好飞书、企业微信或 Telegram 后，以下情况会推送（Telegram 需要 bot token 和 `notify.telegram_chat_id` 两项；在中国大陆访问 api.telegram.org 需要给 stock web 设置 `HTTPS_PROXY`）：

| 时机 | 内容 |
|---|---|
| 日常流程加 `--push`（默认日程的早盘、收盘日报） | 今日要点；各股现价、当日涨跌、事件条数与最高重要性；值得关注的目标价修正（变动 ≥ `tracker.notify_min_change`、论点削弱或失效、立场改变、已排队重跑报告）；简报文件位置 |
| 盘中提醒（默认推送，`--no-push` 关闭） | 24 小时内重要性 ≥ 4 的新事件（带摘要、来源、链接）；新触发的证伪条件及预设动作（复核 / 减仓 / 退出）。同一条只推一次 |
| 深度报告完成 | 「需要你补充的数据」清单（补缺检索后仍缺的关键数据及补充方法） |
| `stock target run --push` | 值得关注的目标价修正（同日报里的那部分） |
| 模拟基金（`stock fund plan/alert/close/weekly --push`） | 标题带「【模拟基金】」：盘前计划、盘中触发提醒、盘后复盘、周报；正文末尾附「模拟组合信号，非投资建议」；超过约 4000 字按基金拆成多条 |
| 状态页「发送测试推送」 | 一条测试消息 |

单条推送过长时会截断（Telegram 约 4000 字、企业微信约 4000 字节）；完整内容在简报与 WebUI 里。

## 事后检验（这套分级到底准不准）

`stock eval [--days 90]` 统计已分级的利好或利空事件发布后 1、5、20 个交易日的超额收益，按重要性和方向分组，给出平均超额收益和方向命中率。

收益按**可交易口径**计算：从消息发布后第一个能成交的收盘价起算。这样，"某股今天大跌 9%"这类新闻所描述的当日波动不会被算成预测成功。样本需要积累几周才有意义。

## 手动补充数据

- **文档**（年报、研报、调研纪要、笔记）：放进 `data/inbox/<公司>/`，下次运行时自动入库，研究 agent 可以检索。也可以运行 `stock docs add 公司 文件`。图片（png/jpg/webp）用本机 tesseract 识别文字后入库（`brew install tesseract tesseract-lang`）。
- **指标**（行业价格、渠道数据等）：`stock data add dongyue R32价格 2026-09 45000 --unit 元/吨`，行业指标的公司名写 `-`；也可以用 CSV 导入：`stock data import x.csv`。
- **消息**：`stock note innolight "渠道：1.6T 订单排到明年二季度"`，会和新闻一起参与分级。
- **一致预期**（港股没有免费数据源）：公司页「业绩 vs 一致预期」卡片，或 `stock consensus set xpeng 2026 --eps -2.4 --currency CNY --n 20 --source 富途`；业绩发布后自动对比（见「业绩 vs 一致预期」）。

简报的"数据缺口"和深度报告的"待补充数据"会列出缺什么、怎么补。

### 网页搜索

补缺检索、行业价格、港股卖方目标价主要靠网页搜索，这是目前最薄弱的一环：
- 免费搜索页都有反爬。同一 IP 短时间请求太多，360 和百度会出验证码，头条返回空结果页，DuckDuckGo 返回验证页，Bing 返回毫不相关的热门网页。程序的对策：360 搜索、头条搜索、Google 新闻三个免费源轮流使用，同一来源每 4 秒最多一次；结果与检索词无关就换源；被拦截的来源暂停（验证码 30 分钟、头条限流 5 分钟）；相同的检索式直接用缓存。全部失败时，agent 会被明确告知「搜索服务不可用」，而不是「信息不存在」。
- 补缺时如果网页搜索大多不可用，下次运行 `stock dossier 公司 --reuse-notes` 会自动重新补缺；也可以加 `--refill` 强制重新补缺（例如配置了付费搜索 API 之后）。
- Google 新闻结果的链接会自动解析成原文地址；头条文章通过移动端接口取正文。
- **Exa**：`.env` 里有 `EXA_API_KEY` 时直接调用 Exa 接口；没有 key 但本机装了 [agent-reach](https://github.com/Panniantong/Agent-Reach) 并配置了 mcporter 的 exa 服务时，经 mcporter 调用 Exa 的免费 MCP——免费额度有限，实测跑完约 3 份报告（约 150 次检索）后返回 HTTP 429，之后自动暂停 1 小时、改用免费搜索源。两种方式都排在所有搜索源之前。Exa 返回带正文摘要的结果，能找到行业价格（生意社、隆众、百川的公开页面）、券商研报摘要、LightCounting/TrendForce 等行业资料；Exa 的网页读取还用来打开富途、雪球这类脚本渲染的页面。程序经 mcporter 调用 Exa，命令和参数固定，不经过 shell。
- **也可以配置付费搜索 API**：在 `.env` 填 `BOCHA_API_KEY`（博查，中文内容覆盖好）、`TAVILY_API_KEY` 或 `SERPER_API_KEY`（Google 结果）之一，程序会优先使用，免费源只作备用。这三个接口按官方文档实现，尚未用真实 key 实测；填好后可以先跑一份报告，看附录「研究过程与出处」里的搜索源。

### ima 知识库

如果你在 [ima](https://ima.qq.com) 里订阅了研报、纪要类的共享知识库，可以把它接进来：
1. 在 https://ima.qq.com/agent-interface 获取 Client ID 与 API Key，填进 `.env` 的 `IMA_CLIENT_ID`、`IMA_API_KEY`。
2. `stock ima list` 查看能访问的知识库，把名称写进 `config.yaml` 的 `sources.ima.knowledge_bases`。
3. `stock ima search 英诺赛科` 试一下检索；`stock ima fetch` 只跑 ima 这一步。

接进来后：
- **每次 `stock run`**：按每家公司的名称、代码（2577.HK 这种写法、A 股 6 位代码、美股代码）、英文名检索标题，新出现的条目作为「ima知识库」来源的消息参与分级，来源名是研报机构或媒体（高盛、彭博社……）。研报等 PDF 原文下载后入库为本公司资料（摘要开头写明资料编号，深度报告和标的追踪都能按页引用）；新闻截图用 tesseract OCR，识别出的文字作为摘要。
- **研究 agent**（深度报告、标的追踪）多了 `ima_search` / `ima_read`，提示词要求卖方观点、目标价、管理层交流优先从这里找。
- **日期**：ima 的条目不带发布时间。程序取标题里的日期（20260929-高盛-…、260310-GS-…），其次是截图 OCR 文字里的日期，再没有就用首次见到的时间。某家公司第一次检索时只收录标题带日期的近期内容，其余只记为已见过，不会把旧内容当新消息。
- **ima 接口的限制**（实测，官方文档没写）：连续约 50 次/分钟会被限流（程序按 1.2 秒间隔调用）；**目录浏览和取原文各有每日次数上限**（各约几十到一百次，超出后当天返回「资料获取次数已达上限」）。所以程序只用检索（不受每日上限限制）来发现新条目，原文按 `max_downloads_per_day`（默认 25，agent 的 `ima_read` 也计入）下载；额度用完时只收录标题，摘要里注明，第二天 agent 可以用 `ima_read` 补读。部分文件 ima 本身就不提供原文（笔记、录音、Excel，以及一些共享文件），只能参考标题。
- **检索只匹配标题**，每个词最多返回约 100 条、不按时间排序。某个检索词命中达到上限时，运行结果会提示「最新条目可能被截掉」；这时可以在 watchlist 给公司加更具体的英文名或别名。盘中 `stock alert` 默认不检索 ima（`in_alert: true` 可开启）。

## 定时运行

**内置调度器**（推荐）：随 `stock web` 运行，日程写在 `config.yaml` 的 `scheduler`，也可在 WebUI「设置 → 日程」修改。默认：工作日 08:30、17:30 运行日常流程并推送（含标的追踪），9–16 点每 20 分钟盘中提醒；选股器事件池工作日 18:00、长线池周六 10:00、主题 agent 每月 1 日；周末深度报告默认关闭（重大事件已会自动重跑单家报告）。模拟基金的日程默认没有加，要用时在 `scheduler.jobs` 里加上 `fund_refresh`（工作日晚间）、`fund_plan`（08:30）、`fund_alert`（每 20 分钟，非交易时段自动跳过）、`fund_close`（17:30）、`fund_weekly`（周六上午）。按北京时间触发；电脑睡眠错过的时点，醒来后在 `catchup_minutes` 内补跑一次。

**系统 cron**（备选，与内置调度器二选一，此时把 `scheduler.enabled` 设为 false）。`crontab -e` 添加（路径按实际情况修改；WebUI 日程页会显示当前日程对应的写法）：

```cron
30 8 * * 1-5   cd /Users/youruser/myProjects/stock && /Users/youruser/.local/bin/uv run stock run --push >> data/cron.log 2>&1
30 17 * * 1-5  cd /Users/youruser/myProjects/stock && /Users/youruser/.local/bin/uv run stock run --push >> data/cron.log 2>&1
*/20 9-16 * * 1-5 cd /Users/youruser/myProjects/stock && /Users/youruser/.local/bin/uv run stock alert >> data/cron.log 2>&1
```

同一时间只运行一个深度报告、日常流程与盘中提醒不重叠：由进程锁（`data/tmp/locks/`）保证，cron 与 WebUI 启动的任务同样适用；上一次还没结束时，新的一次直接跳过。

推送渠道：在 `.env` 中填写 `FEISHU_WEBHOOK`（可选 `FEISHU_SECRET`）、`WECOM_WEBHOOK`，或 `TELEGRAM_BOT_TOKEN` 加上 config 中的 `telegram_chat_id`。

## 局限

- 行情与新闻来自公开网页接口，可能被限流或改版（已做节流、熔断和多源切换）。
- 新闻分级只看标题和摘要；深度报告的 agent 可以读公告原文，但受工具调用轮数限制。
- LLM 的判断和计算参数可能出错。报告中的数字以原始公告为准，重要结论请回到原文核对。
