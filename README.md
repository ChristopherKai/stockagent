# stockagent · 自选股研究系统

自动跟踪自选股的公告、新闻、行情和产业链，用带工具的 LLM agent 做研究，产出三类结果：

- **每日简报**：事件分级（重要性 1–5、方向、相对预期）、技术面、消息发布后的价格反应、论点跟踪。
- **深度报告**（Deep Dossier）：结构参照买方深度报告，包括现状、核心洞见、盈利驱动、资本与稀释、估值（可比公司、反向 DCF、敏感性矩阵）、12 个月情景、证伪条件和催化剂日历。
- **跟踪卡**：把报告里的证伪条件、催化剂、跟踪指标和产业链相关标的存成结构化数据，每天自动检查，触发时推送。

系统辅助研究，**不构成投资建议**，也不会自动下单。

## 工作方式：研究闭环

```
             ┌──────────────────────────────────────────────┐
             ▼                                              │
  数据层：行情 / 公告 / 新闻 / 年报 / 手动补充              │ 跟踪计划：产业链标的、
             │                                              │ 新闻关键词、待补数据
             ▼                                              │
  理解层：公司画像（读年报）→ 深度报告（agent + 工具）───────┘
             │
             ▼
  跟踪层：事件分级 → 证伪条件检查（价格类由代码判定、事件类由 LLM 判定）→ 简报 / 提醒
```

数据采集不是只按公司名搜索：
- 深度报告读完年报、理解业务和产业链之后，会产出一份跟踪计划，写明要盯哪些上下游和同业公司、哪些产业链关键词、哪些行业指标。
- 数据层按这份计划扩大新闻检索和行情采集的范围。
- 自动采集不到的数据列为"待补充"，请使用者手动补充。

## 快速开始

```bash
uv sync                    # 安装依赖（Python 3.12，由 uv 管理）
uv run stock init          # 创建 .env、数据目录和收件箱
# 在 .env 填 key，在 config.yaml 的 llm 部分配置模型
uv run stock llm-test      # 逐个测试模型：连通、JSON 输出
uv run stock run --open    # 日常流程：导入 → 抓取 → 定期报告 → 画像 → 分级 → 证伪检查 → 简报
uv run stock dossier       # 深度报告（每家公司需要若干分钟，建议每周或财报后运行）
uv run stock track         # 查看论点、证伪条件状态、催化剂、跟踪计划
```

## 模型配置（不绑定任何一个模型）

`config.yaml` 的 `llm.profiles` 定义模型端点，`llm.tasks` 指定每个环节用哪个端点：

| 任务 | 作用 |
|---|---|
| `triage` | 事件分级 |
| `stock_brief` / `market_brief` | 个股研判 / 今日要点 |
| `profile` | 公司画像（读年报） |
| `research` | 深度报告的研究 agent（调用工具） |
| `dossier` | 深度报告撰写与跟踪卡 |
| `monitor` | 事件类证伪条件检查 |

每个 profile 的关键参数：

| 参数 | 说明 |
|---|---|
| `protocol` | `openai`（OpenAI 兼容接口：本地网关、DeepSeek、通义、Ollama、vLLM 等）/ `anthropic`（Claude 官方 SDK）/ `mock`（离线演练） |
| `base_url` / `model` / `api_key_env` | 地址、模型名、存放 key 的环境变量（key 写在 `.env`） |
| `tool_mode` | `native`：用接口自带的工具调用；`text`：服务不支持时，用 `<tool_call>` 文本协议 |
| `json_mode` | 是否使用接口的 JSON 模式 |
| `max_input_chars` | 单次最多送入的资料字数；**不填 = 不限制**，只受 `report.profile_max_doc_chars` 控制 |
| `max_tokens` | 单次输出上限。文本输出达到上限时，会自动让模型从中断处续写，最多 `llm.max_continuations` 次；JSON 输出则用该上限重试一次 |
| `fallback` | 本模型不可用（连接失败、5xx、限流、上游拒绝）时自动改用的 profile；失败的模型 10 分钟内不再尝试 |

当前配置：
- 主模型：本地网关上的 `cn:deepseek-v4-flash`。
- 备用：`anthropic/deepseek/deepseek-v4.1-flash[1m]`。
- 备选：`qwen3.8-27b-splash`，没有被任何任务使用，需要时在 `tasks` 里改用即可。

每次调用的 token 用量都记录在数据库里，简报末尾有当日汇总。

## 研究 agent 的工具

| 工具 | 作用 |
|---|---|
| `calculate` | 安全计算器（Python 语法、多行赋值）；只允许数字运算和白名单函数，不能导入模块或访问属性 |
| `dcf_valuation` / `reverse_dcf` | 两阶段 DCF；当前市值隐含的增长率 |
| `valuation_matrix` | 敏感性矩阵：隐含股价 =（倍数 × 驱动指标 + 净现金）÷ 股本 × 汇率 |
| `list_filings` / `search_filings` / `read_filing` | 在已入库的年报、中报、研报、笔记中检索（兼容简繁体，带页码），并读取原文 |
| `market_data` | 任意标的行情与估值（自选股、港股 5 位数字、A 股 6 位数字、美股代码） |
| `financials` | 结构化主要财务指标，A 股和港股多期数据（东方财富数据中心）。港股的报告币种由数据推断（接口里的币种字段不可靠） |
| `broker_research` | 卖方一致预期。A 股：东方财富研报库的评级分布、未来三年 EPS/PE 预测中位数；港股：富途个股预测页的分析师数量与目标价均值/区间（经 Exa 读取） |
| `fcf_yield` | EV 与自由现金流收益率（代码按现金流量表、资产负债表计算）：EV、FCF（TTM、近 3 个年度、3 年平均）、FCF Yield、净现金占市值、Negative EV、FCF 累计覆盖 EV 的年数、前瞻 FCF Yield；另给按总负债计算的保守口径 |
| `valuation_history` | 历史估值分位：当前 PE/PB 处于过去几年的什么位置。港股用日收盘价 ÷ 已披露 EPS，考虑披露滞后并做汇率换算 |
| `sotp` / `ddm` | 分部加总估值（上市子公司、多业务）；股息贴现 |
| `company_events` | 已分级的新闻与公告 |
| `manual_data` | 使用者手动补充的数据 |
| `web_search` / `fetch_url` | 网页搜索（见下方「网页搜索」）；网页与 PDF 全文抓取。头条文章走移动端接口取正文；脚本渲染的网站（富途、雪球）、拒绝程序访问或正文太短的页面改用 Exa 读取；禁止访问本机和内网地址 |

规则写在提示词里：
- 数字必须来自工具，计算必须用工具，每条事实都要注明出处（年报页码、网页来源和日期）。
- 查不到就写"未披露"，不得编造。

报告附录"研究过程与出处"会列出每一次工具调用。撰写前，程序还会按最新行情重新计算 EV / 自由现金流并读取港股一致预期，作为「程序计算」的一节笔记交给撰写环节（复用旧笔记时也不会缺）。

agent 不能直接执行 shell 命令：研究 agent 会读大量不可信的网页，网页里的指令可能诱导它执行任意命令（读取 .env 里的 key、删除文件等）。外部能力一律做成固定的工具（程序和参数固定，参数只当数据传递）。

agent 参数在 `config.yaml` 的 `agent` 部分：最多几轮工具调用、单次工具结果的长度、搜索源、研究子任务是否并行。

## 深度报告与跟踪卡

`stock dossier [公司]` 的流程：
1. **研究**：4 个研究子 agent（业务与产业链、财务与资本、市场与估值、近期动态与风险）并行调用工具查证，写出研究笔记，完成后立即存盘。
2. **补缺检索**：从笔记中找出对多空判断最关键、但还没拿到的数据（如行业配额与价格、公司获配额度、卖方一致预期），由补缺 agent 换不同检索式专门搜索，并打开原文核实。仍找不到或只找到一部分（包括只有未经核实的来源）的，生成「需要你补充的数据」：已经有什么、还缺什么、为什么关键、从哪里获取、怎么补充。这些请求存入数据库，会在命令输出、简报和推送里提示；`stock requests` 可查看或关闭。
3. **撰写**：先从笔记中列出 12–20 条「必须覆盖的关键事实」（核心财务、分部、股权、资本运作、异常变化如应收票据激增），连同笔记和你补充的数据一起交给撰写环节。分两段撰写，只以这些材料为事实来源；笔记里已有的数据不得写成「未披露」。单段超出输出上限时，自动让模型从中断处续写。
4. **一致性核对**：把报告中所有「未披露/未查到」的说法逐条与研究笔记核对，笔记里其实有数据的，改写原句补上数据和出处。跟踪卡里的「待补充数据」也做同样核对。
5. **覆盖检查**：逐条检查关键事实是否写进了报告，遗漏的补一两句（带数字和出处）插入对应章节末尾。第 4、5 步的修改记录都附在报告附录。
6. 抽取跟踪卡（JSON，经过校验）：
   - 证伪条件：价格类的写明指标、上市地、阈值和动作（复核 / 减仓 / 退出），由代码每日判定；其余由 LLM 对照新事件判定，状态只升级不回退。
   - 催化剂日历（带可检验的 KPI）、跟踪指标、产业链相关标的、新闻跟踪词、待补充数据。
7. 数字溯源：检查报告中的数字能否在研究笔记或工具结果中找到对应（允许四舍五入和亿/万/千元换算），找不到出处的数字列在附录，提示人工核对。
8. 输出 `data/dossiers/<公司>_<时间>.html`（本机有 Chrome 时同时导出 PDF，使用独立的临时配置目录，不碰日常 Chrome）。跟踪计划写回数据库，下一次抓取即生效。

补充说明：
- 研究笔记完成后立即存盘（`data/dossiers/notes/`）。如果撰写阶段失败，运行 `stock dossier 公司 --reuse-notes` 可以跳过研究直接撰写；失败的研究子任务会单独重做。
- 数据请求的闭环：按报告附录「需要你补充的数据」补充数据（`stock data add`）或文件（`data/inbox/<公司>/`）后，运行 `stock dossier 公司 --reuse-notes`。程序发现上次补缺之后有新补充的数据，会带着上一轮的结果重新补缺，补充的数据也会直接交给撰写环节。新报告不再列出的旧请求（已查到或不再关键）自动标记为已解决。
- 重新生成报告时，上一版中已触发或出现苗头的证伪条件会交给新报告重新核实，不会被悄悄清零；旧记录保留在数据库里。
- 深度报告超过 `report.dossier_stale_days`（默认 30 天）时，简报会提示更新。

## 事后检验（这套分级到底准不准）

`stock eval [--days 90]` 统计已分级的利好或利空事件发布后 1、5、20 个交易日的超额收益，按重要性和方向分组，给出平均超额收益和方向命中率。

收益按**可交易口径**计算：从消息发布后第一个能成交的收盘价起算。这样，"某股今天大跌 9%"这类新闻所描述的当日波动不会被算成预测成功。样本需要积累几周才有意义。

## 手动补充数据

- **文档**（年报、研报、调研纪要、笔记）：放进 `data/inbox/<公司>/`，下次运行时自动入库，研究 agent 可以检索。也可以运行 `stock docs add 公司 文件`。
- **指标**（行业价格、渠道数据等）：`stock data add dongyue R32价格 2026-09 45000 --unit 元/吨`，行业指标的公司名写 `-`；也可以用 CSV 导入：`stock data import x.csv`。
- **消息**：`stock note innolight "渠道：1.6T 订单排到明年二季度"`，会和新闻一起参与分级。

简报的"数据缺口"和深度报告的"待补充数据"会列出缺什么、怎么补。

## 数据来源

| 类型 | 来源 |
|---|---|
| 行情 | 东方财富 → 腾讯财经（前者被限流时自动切换，熔断 60 分钟） |
| 港股公告、年报/中报 | 港交所披露易 |
| A 股公告、年报/半年报 | 巨潮资讯 |
| 美股申报文件 | SEC EDGAR（需在 config.yaml 设置 `sec_user_agent`） |
| 新闻 | 东方财富资讯、Google News（简中 / 繁中香港 / 英文），以及跟踪计划里的产业链关键词 |
| 汇率（AH 溢价、币种换算） | 东方财富 → Frankfurter（欧洲央行参考汇率） |
| 结构化财务指标（A 股、港股） | 东方财富数据中心 |
| 卖方研报、评级与盈利预测（A 股） | 东方财富研报库 |
| A 股估值历史（PE/PB） | 东方财富数据中心 |
| 港股南向资金持股 | 东方财富数据中心（沪港通、深港通合计） |
| 网页搜索（行业价格、政策、港股卖方观点等） | 付费 API（博查 / Tavily / Serper，填了 key 才用）优先；免费的 360 搜索、头条搜索、Google 新闻轮流使用，百度、Bing、DuckDuckGo 备用 |

### 网页搜索

补缺检索、行业价格、港股卖方目标价主要靠网页搜索，这是目前最薄弱的一环：
- 免费搜索页都有反爬。同一 IP 短时间请求太多，360 和百度会出验证码，头条返回空结果页，DuckDuckGo 返回验证页，Bing 返回毫不相关的热门网页。程序的对策：360 搜索、头条搜索、Google 新闻三个免费源轮流使用，同一来源每 4 秒最多一次；结果与检索词无关就换源；被拦截的来源暂停（验证码 30 分钟、头条限流 5 分钟）；相同的检索式直接用缓存。全部失败时，agent 会被明确告知「搜索服务不可用」，而不是「信息不存在」。
- 补缺时如果网页搜索大多不可用，下次运行 `stock dossier 公司 --reuse-notes` 会自动重新补缺；也可以加 `--refill` 强制重新补缺（例如配置了付费搜索 API 之后）。
- Google 新闻结果的链接会自动解析成原文地址；头条文章通过移动端接口取正文。
- **Exa**：`.env` 里有 `EXA_API_KEY` 时直接调用 Exa 接口；没有 key 但本机装了 [agent-reach](https://github.com/Panniantong/Agent-Reach) 并配置了 mcporter 的 exa 服务时，经 mcporter 调用 Exa 的免费 MCP——免费额度有限，实测跑完约 3 份报告（约 150 次检索）后返回 HTTP 429，之后自动暂停 1 小时、改用免费搜索源。两种方式都排在所有搜索源之前。Exa 返回带正文摘要的结果，能找到行业价格（生意社、隆众、百川的公开页面）、券商研报摘要、LightCounting/TrendForce 等行业资料；Exa 的网页读取还用来打开富途、雪球这类脚本渲染的页面。程序经 mcporter 调用 Exa，命令和参数固定，不经过 shell。
- **也可以配置付费搜索 API**：在 `.env` 填 `BOCHA_API_KEY`（博查，中文内容覆盖好）、`TAVILY_API_KEY` 或 `SERPER_API_KEY`（Google 结果）之一，程序会优先使用，免费源只作备用。这三个接口按官方文档实现，尚未用真实 key 实测；填好后可以先跑一份报告，看附录「研究过程与出处」里的搜索源。

## 常用命令

| 命令 | 作用 |
|---|---|
| `stock run [--push] [--open] [--no-llm]` | 日常完整流程 |
| `stock alert [--no-push]` | 盘中：抓取 → 分级 → 证伪检查 → 推送重要事件和触发的证伪条件 |
| `stock dossier [公司] [--open] [--reuse-notes]` | 生成深度报告与跟踪卡（可复用已保存的研究笔记） |
| `stock track [公司] [--check]` | 查看或检查论点跟踪 |
| `stock requests [公司] [--done 编号]` | 查看或关闭「需要你补充的数据」 |
| `stock eval [公司] [--days 90]` | 事后检验：事件分级的方向与重要性有没有预测力 |
| `stock profile [公司] [--force]` | 重新生成公司画像 |
| `stock events [公司] --days 3 --min 3` | 查看已分级事件 |
| `stock docs fetch/add/list`、`stock data add/import/list`、`stock note` | 资料与手动数据 |
| `stock llm-test [--profile 名称]`、`stock status` | 检查配置 |

## 局限

- 行情与新闻来自公开网页接口，可能被限流或改版（已做节流、熔断和多源切换）。
- 新闻分级只看标题和摘要；深度报告的 agent 可以读公告原文，但受工具调用轮数限制。
- LLM 的判断和计算参数可能出错。报告中的数字以原始公告为准，重要结论请回到原文核对。
