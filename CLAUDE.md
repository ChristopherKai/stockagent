# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`stockagent` (CLI `stock`) is a research system for a watchlist of HK / A-share / US stocks. It collects prices, announcements and news; an LLM grades each event; tool-using research agents write deep dossiers ending in machine-checkable kill criteria; a tracker revises each dossier's valuation as new events arrive (target price = scenario-weighted valuation computed in code); and it produces daily briefs, push alerts and a local WebUI (`stock web`) with a built-in scheduler. It is a research aid only: it places no orders and gives no buy/sell ratings; the target price is labelled 「目标价（情景加权估值）」 with a disclaimer everywhere it appears. The one carve-out is the labelled **paper funds** (`stock fund`, `fund/`): simulated portfolios whose rule-based suggestions are booked on a paper ledger. They never connect to a broker or place orders, every push is titled 「【模拟基金】」 and ends with 「模拟组合信号，非投资建议」 (`fund.report.DISCLAIMER`), and nothing outside `fund/` gives position advice (the report chat may only relay paper-fund state with that label, chat.py rule 8). README.md (Chinese) is the user manual. Prompts, CLI output, comments and reports are all Simplified Chinese, so keep new user-facing strings in Chinese.

## Commands

```bash
uv sync                                                # Python 3.12, managed by uv
uv run pytest -q                                       # whole suite, ~10 s, fully offline
uv run pytest tests/test_agent.py::test_safe_calc -q   # one test
uv run pytest -k search_filings -q
uv run stock llm-test [--profile NAME]                 # probe each LLM profile (text + JSON)
uv run stock status                                    # DB counts, task→model routing, push channels
uv run stock -v run [company ...] [--no-llm]           # daily pipeline; -v (before the subcommand) = INFO logs
uv run stock dossier <company> [--reuse-notes] [--refill]   # deep report, several minutes per company
uv run stock target add|list|show|run|rebase|remove <company>  # tracker: code-built baseline, event-driven revisions
uv run stock web [--port 8765] [--no-scheduler] [--jobs-only] [--open]  # WebUI on 127.0.0.1 + job runner + scheduler; --no-scheduler also disables the JOB RUNNER (submitted jobs stay queued forever); --jobs-only = runner without scheduler (for test instances)
uv run stock screen refresh|run|show|promote|themes|eval        # screener: HK Connect + A-share universe → candidates
uv run stock consensus show|set|check [company]                 # earnings vs pre-release consensus (set = manual entry, HK)
uv run stock fund sync|refresh|plan|alert|close|weekly|status|resume [--dry-run]   # paper funds (funds.yaml); --dry-run = no DB writes, no push
```

- There is no linter config or linter dependency. The `.ruff_cache/` shows ruff has only been run ad hoc (`uvx ruff check src tests`).
- Run the CLI from the repo root. It reads `./config.yaml`, `./watchlist.yaml` and `./.env` (`-c` overrides the config path).
- `company` args accept a watchlist id, name, alias or code; omit them to mean all companies.
- Production runs from the built-in scheduler inside `stock web` (config `scheduler.jobs`, cron syntax in Asia/Shanghai; README 「定时运行」 has a launchd plist): `stock run --push` twice on weekdays (includes the tracker step), `stock alert` every 20 min in market hours. System cron is the alternative; never enable both.
- **Adding a company:** `stock add <name or code> [--onboard]` / `stock add <HK|A|US> <code>` (or the 观察清单 page's one-click form → `add_company` job; names are validated by `newco.check_query` before going into argv and resolved to a code in the job via Eastmoney suggest, stocks only) looks up name / English name / industry / main business and the company's other listings via Eastmoney datacenter F10 profiles (`emdata.company_profile`, linked across markets by `ORG_CODE`), writes the entry with `yamledit`, then runs the onboarding chain. The WebUI's `AppHolder.app` reloads when `watchlist.yaml`'s mtime changes. Manually: add an entry to `watchlist.yaml` (listings with `market`/`code`/`benchmark`; `notes`, `watch_items`, `news_queries` become LLM context), or use the WebUI's 观察清单 page. Then run `stock fetch <id>` → `stock docs fetch <id>` → `stock triage <id>` → `stock profile <id>` → `stock dossier <id>` → `stock target add <id>` (the WebUI's 「新公司初始化」 job runs the same chain).

## Architecture

**Context object.** `App.load()` (app.py) builds `App(settings, watchlist, db, llm)` from config.yaml, watchlist.yaml and .env. Nearly every module function takes `app` first. Config and watchlist are pydantic models (config.py).

**Storage.** One SQLite file, `data/stock.db` (db.py: WAL mode, shared across threads behind an RLock).
- Timestamps are stored as UTC ISO strings; `utils.iso()` rejects naive datetimes. Display is in `CST` (Asia/Shanghai).
- **No migrations:** the schema is `CREATE TABLE IF NOT EXISTS`, so a column added to `SCHEMA` never reaches an existing DB. Write an explicit migration.
- The `kv` table holds cross-run state:
  - filing watermarks `fetched:filings:<HK:00100>`. The first fetch only looks back `announcements_lookback_days`, and raising it later does not backfill.
  - per-source circuit breakers `down:<source>`: 60 min, shared by every process.
  - cached external IDs: `hkex_stock_id:`, `cninfo_org_id:`, `sec_cik:`, `em_secid:`, `us_secid:`.
  - once-a-day markers: `reports_checked:`, `monitor_checked:`, `ccass_checked:<HK:01234>`, `consensus_checked:<company>` (consensus snapshot).
  - `earnings:<company>`: JSON state of the earnings check — `since` (first check − `consensus.lookback_days`; A-share releases before it are never processed), `period` (latest HK period seen) and `pending` (HK release waiting for a manual pre-release consensus, given up after 30 days).
  - scheduler fire markers `sched_last:<schedule name>` (last minute fired, CST ISO).
  - paper funds: `hk_lot:<code>` (HK board lot from the Tencent quote, `<lot>@<date>`), `fund_alert:<date>:<fund>:<secid>:<kind>` (one intraday alert per stock/kind/day).
  - ima: `ima_kb:<configured name>` (resolved `{id, name}`), `fetched:ima:<kb_id>:<company>` (first-search marker), `ima_downloads` (today's original-file budget `{date, n, exhausted}`).
- `ccass` table: one CCASS snapshot per (HK code, date), top `sources.ccass_keep` participants only (`db.save_ccass` / `db.ccass(code, on_or_before)`).
- `consensus` table: consensus snapshots per (company, source `em_a`|`nasdaq`|`manual`, taken_on, fiscal_year, metric `eps`|`profit`|`revenue`); profit/revenue in 元, `per_ads` marks Nasdaq ADS figures. `earnings` table: one row per (company, period end, stage `report`|`forecast`|`express`) with the comparison JSON and the generated item uid (null when no consensus was available).
- Tracker tables: `trackers` (one row per tracked company; points at the current baseline dossier and latest revision), `revisions` (baseline / revision / review snapshots with the full model JSON, applied and rejected changes, assessed evidence, trigger-status snapshot), `tracker_refs` (primary key `(company_id, ref)`: every piece of evidence the tracker has shown to the model, so nothing is processed twice). `jobs` holds WebUI / scheduler / tracker-queued background jobs.
- Process locks live in `data/tmp/locks/*.lock` (fcntl.flock, released when the process dies): `dossier`, `pipeline` (run / alert / target run), `web` (only one scheduler + job runner), `screen`, `fund` (all `stock fund` commands except `status`). `PRAGMA user_version` is set (currently 4: v2 `chat_messages.trace_json`, v3 `chats.revision_id`, v4 `triggers.direction`); new columns on existing tables go in `db.MIGRATIONS` (version → columns, added with ALTER if missing).
- `data/` is gitignored, generated output: the DB; `docs/` (originals plus extracted `.txt`); `dossiers/` (html/md/pdf plus `notes/*.json`); `reports/`; `inbox/`; `tmp/`.

**Instrument keys.** The Eastmoney `secid` keys all price data:
- `116.00100` HK; `1.` SH; `0.` SZ/BJ; `105/106/107.TICKER` US.
- `100.HSI` / `124.HSTECH` indices; `133.HKDCNH` FX.

`bars`/`quotes` rows use it, and the Tencent and Frankfurter fallbacks translate from it. Watchlist listings use `Listing.key`, e.g. `HK:00100`.

**Multiple listings.** `Company.pricing_listing` (watchlist `pricing: HK|A|US`, else HK > A > US) is the listing that scenario prices, target price and price kill criteria use; never use `listings[0]` for that. The dossier stores it on the card (`card.price_listing`, set in code) and `valuation.build_baseline` reads it (old cards fall back to `listings[0]`, which is how they were priced). US listings may carry `ads_ratio` (ordinary shares per ADS): `app.cross_premiums` returns the AH premium and the ADS-vs-HK premium; `valuation.equivalents` converts a target to other listings by the current price ratio (same upside) plus an FX parity line; `quote_shares(quote, listing)` multiplies ADS counts by the ratio; `tools.fcf_snapshot` keeps A-share statements for A+H companies but prices EV on the pricing listing (other listings get one line each, from stored quotes only).

**Data layer** (`sources/`, `app.fetch`, docs.py).
- Adapters return plain dicts. `app._try` applies the circuit breaker; `app._guard` stops one failing source from aborting a run. `sources.price_sources` sets the fallback order.
- Documents are copied to `data/docs/<company>/`, deduped by SHA-256, and text-extracted with a `[第N页]` marker per page. `tools.split_pages`, `search_filings` and the citation format depend on those markers.
- Filing search converts both query and text to Simplified Chinese (`utils.to_simplified`). Never convert the other way.
- `docs.fetch_reports` only downloads documents in HKEX/cninfo's annual and interim *report* categories, skipping any `(doc_type, period)` that already exists. When adding something like a results announcement by hand, give it `--type other`; typing it `interim_report` would stop the real report from ever downloading.
- **Statements & holders:** `emdata.statement` (full income/balance/cash-flow; A wide table with curated `A_STATEMENT_ITEMS`, HK long table pivoted by `STD_ITEM_CODE`), `emdata.a_holders` / `a_holder_counts` / `hk_holders`. US statements come from SEC XBRL companyfacts (`sec.company_facts`, cached 1 h per process; `sec.statement_from_facts` merges concepts per period, picks the shortest duration per end date, so 10-Q income is single-quarter and cash flow is YTD); needs `sources.sec_user_agent`. XBRL details: us-gaap concepts, else `IFRS_ITEMS` (ifrs-full filers); cost of revenue takes the largest concept per period (`PICK_MAX`); EPS off by >20× vs net income ÷ weighted shares is dropped with a note (BE's 10-Q mis-tags); Q4 single quarter (= FY − 9M YTD) and TTM are derived in code (`derive_flows`, columns labelled 「推导」); `tools._us_stale_note` re-fetches companyfacts (bypassing the cache) when a newer 10-K/10-Q is filed than XBRL has, else flags ⚠ in the table header (SEC's companyfacts can lag filings by weeks). **US filings as documents:** `docs.report_candidates` for US-only companies (no A/HK listing) takes 10-K/20-F/40-F → `annual_report` (period = year) and 10-Q → `quarterly_report` (period = report date, not Q1–Q4: fiscal years differ) via `sec.reports`; `htmltext.html_text` turns the primary HTML into text with `[第N页]` markers from page-break styles (iXBRL header dropped, table rows joined with `|`). 8-K / 6-K announcements get the EX-99.1 press release start as snippet `[新闻稿正文]` (`sec.exhibit_text`, `app._add_exhibits`, ≤12 per run) and 8-K item codes get Chinese labels. **US structured tools** (`usdata.py`, all derived from SEC XBRL via `usdata.load_facts`, which also refetches/flags stale companyfacts): `fcf_yield` (`usdata.fcf_data` → same shape as `emdata.fcf_data`, so `fcf.metrics` is shared; capex = PP&E + capitalised software, debt = short + current + long-term incl. converts, leases excluded), `valuation_history` (`tools.us_valuation_series`: close ÷ TTM EPS / BPS, ADS via `ads_ratio`, CNY filers via USD/CNH; mis-tagged EPS dropped by `usdata._clean_eps`), `financials` (`usdata.indicators_table`, only for US-only companies), `shareholders` (Nasdaq 13F summary + Form 4 summary/recent + SEC 13D/G filing links) and `short_interest` (Nasdaq short interest for Nasdaq-listed, else FINRA bi-weekly `shrt<date>.csv`; plus FINRA RegSHO daily short-volume ratio — not net short). US-only companies also store the 3 latest 10-K/20-F, the latest 10-Q and the latest DEF 14A (`other`, period `DEF14A-<year>`), and results press releases (8-K item 2.02, 6-K with results-like title) as `other` documents (`app._store_release`). Price sources: `sina` (US only: daily bars + quote with market cap) is a third fallback; Tencent's US quote endpoint needs the symbol without exchange suffix (`usBE`), its K-line endpoint needs it (`usBE.N`). Yahoo (429) and Stooq (404) do not work from here. US consensus: `sources/nasdaq.py` (Yahoo returns 429 from mainland IPs). Columns carry their period length; flows are YTD cumulative for A/HK.
- **CCASS** (`sources/ccass.py`): HKEX `searchsdw` ASP.NET form (GET for `__VIEWSTATE`, then POST), last 12 months only, T+1. `app.fetch_ccass` runs inside `fetch` only when `market` is on (so not in `stock alert`), once a day per HK listing; the first run only stores a snapshot, later runs compare with the previous stored snapshot and add one `items` row (kind `data`, source `ccass`) when a participant moves ≥ `ccass_alert_pct` points of issued shares. The `ccass` tool fetches missing ~7/28-day-back baselines on demand via `app.ccass_snapshot`.
- Images (png/jpg/webp) are OCR'd by local tesseract (`docs.ocr_image`, fixed argv, `chi_sim+eng`).
- **ima knowledge base** (`sources/ima.py` HTTP client, `imafeed.py`): official OpenAPI with `IMA_CLIENT_ID`/`IMA_API_KEY` from `.env`. Undocumented limits found in real use: ~50 calls/min → `200001` (HTTP 403); `get_knowledge_list` and `get_media_info` each have a **daily** cap (tens to ~100) → `220021`; `220030` = that file has no original. So the feed never browses folders: per company it searches titles (`queries()`: name, `2577.HK`-style code, A code, US ticker, latin names; search is title-substring, ≤~100 hits, unordered, no AND), re-checks with `Matcher`, dedupes via the `ima_seen` table (`(media_id, company_id)`), dates from the title (else OCR text, else first-seen; a company's first search only takes dated items). New entries become `items` (kind `news`, source `ima`, `source_name` = broker/media); PDFs are stored as `research`/`transcript` docs (source `ima`) under the daily `max_downloads_per_day` budget. Tracker skips source-`ima` docs as evidence (the item already names the doc). `stock alert` skips ima unless `sources.ima.in_alert`.
- **Twitter/X** (`sources/twitter.py` adapter, `twitterfeed.py` feed, tools `twitter_search` / `twitter_user`): wraps the external `twitter-cli` with fixed argv (read-only `search` / `user-posts`; the operand goes after `--` and all options (incl. `--json`) before it; handles validated against `[A-Za-z0-9_]{1,15}`), credentials `TWITTER_AUTH_TOKEN`/`TWITTER_CT0` from `.env` else `~/.agent-reach/config.yaml`, passed only via the subprocess env. **Never run it without credentials**: upstream then falls back to reading browser cookies. Auth/rate-limit/unavailable errors trip the shared `down:twitter` breaker (`app._trip`); `not_found`/`invalid` don't. Two independent switches under `sources.twitter` (WebUI 设置 → 通用 → 推特 / X): `agent_tools` (tools exist only when on and `twitter.available()`; dossier, tracker; not chat, not screener; the tracker drops them with `tracker.web_search: false`) and `news_feed` (default on; `fetch(twitter=...)`, runs in `stock run`/`fetch`, not `stock alert`). The feed runs inside `app.fetch` (step 2/6 of `stock run`, also `stock fetch`; not `stock alert`), BEFORE triage (4/6) and the tracker (5/6): the tracker only consumes already-triaged `items`, like every other news source, so tweets fetched later would miss grading until the next run. `sources.twitter.feed_scope` (`all` default | `tracked` = only companies with an enabled tracker; also limits the routing digest) bounds the companies. The feed has four inputs. (1) Global `sources.twitter.shared_accounts` (newswires; newest `shared_max_per_account` posts each, ≤200 — twitter-cli paginates): **no keyword matching and no per-company fan-out**. New posts are routed in batched model calls (`triage_batch_size` per call, concurrent over `llm.concurrency`) given `company_digest()` (id, name/codes, sector, plan keywords, related names for the in-scope companies); the model returns the company ids each post relates to (≤ `shared_route_max`, possibly none). Only routed companies get `items` rows, and that company's own triage then judges it from its profile (rule 13). `twitter_routed` remembers posts already routed (empty = unrelated) so they are never re-sent; if the model is unavailable or the call fails nothing is marked and the posts are retried next run. (2) Per-company `twitter_official` and `twitter_accounts` (newest `feed_max_per_query` posts each; **no `Matcher` either** — the company's own triage judges relevance). (3) Name searches, **English first, Chinese in moderation** (every search passes `--lang`): English terms (`$TICKER`, English name/aliases, ≤ `feed_queries_per_company`) joined into ONE `($A OR B OR "C D")` query with `lang=en` (parentheses matter: the CLI appends `min_faves`/`since` filters, and AND binds tighter than OR), plus the Chinese name once with `lang=zh` (`feed_chinese_name`). (4) The first `feed_plan_keywords` entries of the dossier plan's `news_keywords` (same plan `fetch_news` uses) as **English translations** (`translate_terms`: one batched `triage`-routed model call per 40 new keywords, cached forever in kv `twitter_terms_en` as `{中文词: 英文词}`, `""` = untranslatable, non-English output rejected; keywords without a translation fall back to the Chinese original) with `lang=en`, plus `feed_plan_keywords_zh` Chinese originals with `lang=zh`; hits are exempt from `Matcher` and tagged `[跟踪词：<original Chinese keyword>]` so triage rule 10 judges them. Searches whose language is not in `feed_languages` are skipped. A per-run call budget `feed_max_calls` (X allows only ~50 searches per 15 min; exceeding gives 429 → `down:twitter` breaker) is spent company by company in rotation; the next start is kept in kv `twitter_cursor` (only moved by runs covering the whole scope). **Trust levels** are encoded in the snippet prefix (`sources/twitter.py`: `TAG` `[推特·未经证实]`, `SHARED_TAG` `[共享账号·已分流]`, `OFFICIAL_TAG` `[官方账号]`, `ACCOUNT_TAG` `[登记账号]`; triage rules 12–15): every account the user registered (shared accounts, a company's `twitter_official`, a company's `twitter_accounts`) is a trusted source and its posts are treated as **confirmed news** (graded normally, **no materiality cap**, can become tracker evidence and push alerts); only name/keyword search hits by arbitrary authors are unconfirmed and **code caps their materiality at `feed_max_materiality`** (default 2, below `tracker.min_materiality`). The research agents get the same distinction: `ToolBox._tweet_lines` marks posts by registered accounts `【可信账号·<role>】` (`twitterfeed.account_roles`: official > company account > shared), `twitter_user` says whether the handle is registered, and dossier/gap-fill/tracker prompts append `twitterfeed.accounts_line()` (the company's registered accounts) after `twitter.HINT`; posts from any other author stay leads, never evidence for numbers (`twitter_search` has a `lang` param; the hint says English first, `lang=zh` only for China-specific concepts). Account discovery (`sources.twitter.discover`): search- and plan-keyword-origin posts that passed the feed filters are recorded in `twitter_authors` (per post×company, refreshed likes); `twitterfeed.candidates()` aggregates by handle (≥ `discover_min_posts` distinct posts within `discover_days`, excluding registered and dismissed handles in `twitter_dismissed`); the WebUI accepts a candidate into `shared_accounts` (config) or a company field (`yamledit.add_company_handle`) — never automatically.
- **Consensus & results** (`emdata`): `research_reports(begin=, end=)` pages through the report library and maps each report's EPS to fiscal years by publish year (`report_years`; checked on real 2025/2026 reports); `a_consensus` = `RPT_WEB_RESPREDICT` (current aggregate), `a_forecasts` = 业绩预告 (归母净利 range), `a_express` = 业绩快报. Nasdaq: `yearly_eps`, `earnings_surprise` (through `_get(..., kind="company")`). HK has no free EPS consensus source (only ratings / target prices in `RPT_HKF10_INFO_ORGRATING`), hence manual entry.
- Users add material via `data/inbox/<company>/` (imported by `stock run`), `stock docs add`, `stock data add`, `stock note` and `stock consensus set` (or the company page).

**LLM layer** (llm.py).
- Tasks (`triage`, `stock_brief`, `market_brief`, `profile`, `research`, `dossier`, `review`, `monitor`, `tracker`, `chat`, `screen`, `screen_theme`) route to profiles via `llm.tasks`. Protocols: `anthropic`, `openai` (any compatible endpoint) and `mock`.
- `complete()`: JSON-schema output plus a pydantic `validate` hook, retried once with the parse error appended. Truncated text is auto-continued up to `max_continuations` times.
- `run_agent()`: the tool loop, using native tool calls or a `<tool_call>` text protocol (`tool_mode: text`). Optional `history` (prior text-only user/assistant turns) is placed before the current user message.
- Fallback: retryable failures (connection errors, 402/403/408/409/429/5xx) move down the profile's `fallback` chain. A failed profile is tried last for the next 120 s.
- Every call is logged to `llm_calls`.
- `mock` fabricates schema-valid JSON and echoes any `id=` values in the prompt; the tests rely on this.

**Pipelines.**
- **Triage** (triage.py): a conservative title dedupe runs in code, then batches go to the LLM along with the last 3 days of graded events for cross-batch dedupe. Items the model drops get `triage_attempts` bumped; items stop being retried after 3 attempts.
- **Profile** (profile.py): uses the latest annual and interim reports plus up to 3 other docs. Input is budgeted by `report.profile_max_doc_chars` (and the profile's optional `max_input_chars`), excerpting around key section headings.
- **Dossier** (dossier.py), the core pipeline, in order:
  1. 4 research sub-agents (`SECTIONS`) run in parallel, each with a fresh `ToolBox`.
  2. Notes are saved to `data/dossiers/notes/` straight away, so `--reuse-notes` can skip research and redo only failed sections. Sections that failed (`FAILED_MARK`) are redone once automatically (`_redo_failed`, fresh runs and reuse alike); if any still fails `generate` raises `LLMError` before gap-fill and writing (notes stay saved), so a report is never written from missing sections.
  3. A gap-fill agent searches for missing data; whatever it can't find becomes `data_requests` for the user.
  4. Scenario pricing (`scenarios.py`, see below), then the report is written in two parts.
  5. 「未披露」 claims are audited against the notes.
  6. A key-facts coverage check adds anything missed.
  6b. Numbers with no source (`verify.check` against notes, tool output, supplied data) go back to the model once (`revise_unverified`, sees notes + full report): keep (derived) / fix / remove. Code rejects a rewrite that introduces unsourced numbers (and table rewrites that change the column count); applied edits are listed in the appendix 「数字修订」.
  6c. Adversarial review (`review.py`, `report.review`, task `review`, routable to a different model): one `complete("review")` call reads notes + report as a counter-side reviewer and returns a counter-case plus objections (`ignored_evidence | overreach | inconsistent | unsupported | missing_risk`). Code vets them (`vet`): the quote must be found verbatim (normalised) in the report and the evidence verbatim in the notes, else the objection is dropped (`ignored_evidence`/`inconsistent`) or demoted (high → medium, `missing_risk` → low). Medium/high fixable objections get ONE patch round via `complete("dossier")`; a patch is rejected if it adds numbers `verify.check` cannot source, changes a table row's column count, or touches the program-priced 「12 个月情景」 section. Unfixed objections are kept, not hidden: appendix 「审稿意见」 and `notes["review"]` (excluded from `_provenance_sources`; the report chat's `report_notes` can search it). Failure of either call skips that step. The review call's initial `max_tokens` is `review.REVIEW_MAX_TOKENS` (reasoning models spend ~30k on it).
  7. The tracking card is extracted (pydantic `Card`); code then adds `price_listing` (the pricing listing) and `stats` (scenario stats + stance check). When scenario pricing succeeded, `card["scenarios"]` is overwritten with the code-priced ones and `card["valuation_spec"]` stores the parameters.
  8. `db.save_dossier` deactivates old triggers and replaces catalysts and the plan.
  9. Output is rendered to HTML/MD, and to PDF via headless Chrome with a throwaway profile in `data/tmp/`. `verify.py` lists report numbers not traceable to notes or tool output.
- **Program-priced scenarios** (scenarios.py, no hand-copied prices): before writing, the model only *selects points* in what the research tools already computed; prices come from code. Menu = `valuation_matrix` calls (price = `tools.matrix_price`) and `sotp` calls (`tools.sotp_price`: (Σ driver × multiple × stake × (1 − discount) + net cash) × (1 − holdco discount) ÷ shares × fx). `sotp` parts may carry `driver` + `multiple` (value-only parts = driver = value, multiple = 1); calls with the same part names / stakes / shares / net cash / fx merge into one SOTP whose per-part driver, multiple and discount values (and the holdco discounts) form the allowed ranges (±10 %, discounts ±5 pts) — the research prompt asks for one call per bull/base/bear, discounts and holdco discount may vary by scenario, drivers may be negative (HQ costs). `build_spec` validates (ranges, bull ≥ base ≥ bear, base > 0; failure → retried once with the reason, then falls back to the old flow of extracting prices from the report text). The selector follows the anchor the valuation notes designate (`SYSTEM`: no preference for SOTP; no designation → matrix). If both kinds exist the other kind is picked once more as a cross-check: base prices differing by > `DIVERGENCE` (30 %, relative to the matrix) → a SOTP primary falls back to the matrix; either way `spec["cross_check"]` records it (research note, ⚠ line in the card appendix). The result goes into the notes as 「12 个月情景（程序计算）」 (writer must copy it), `card["scenarios"]`, and `card["valuation_spec"]` (kind `matrix`|`sotp`; `report_mismatch` lists code prices not found in the report's scenario section). `valuation.build_baseline` rebuilds from `valuation_spec` exactly (falls back to inferring from the tool log for old cards or malformed specs). `ValuationModel.method="sotp"`: `ScenarioPoint.segments` (`Segment`: driver, multiple, stake, discount), per-scenario `holdco_discount`; tracker paths are `bull.p1.driver` / `all.p2.multiple` (p1 = first segment). SOTP profits must be on an attributable basis (stake = real holding); the prompt asks for it but code can't verify it — the cross-check is the real guard.
- **Feedback loop:**
  - The card's plan (`related_tickers`, `news_keywords`) widens what `fetch_news` and `fetch_market` collect.
  - monitor.py checks kill criteria on each run: price metrics in code, fundamental/event ones by LLM. Status only escalates (ok → warning → triggered).
  - Non-ok criteria are fed into the next dossier (`previous_alerts`).
- **Earnings vs consensus** (consensus.py; runs inside step 2/6 of `stock run`, after fetch; not in `stock alert`; no LLM):
  1. `snapshot`: once a day per company, store the current A-share aggregate (`em_a`) and Nasdaq yearly EPS (`nasdaq`) in `consensus`.
  2. `check`: A shares (A+H on the A-share basis, CNY) look at 定期报告 rows with 公告日, 业绩预告 and 业绩快报 whose notice ≥ `since`; the pre-release consensus is rebuilt from the report library (each broker's latest report in the `window_days` before the notice, median EPS), or the latest `em_a` snapshot before the notice when the library has fewer than `min_estimates` brokers. HK (and HK+US) have no notice dates: the release date comes from an HKEX announcement in the [中期業績]/[末期業績]/[季度業績] categories (the full 中期報告 a month later does not count) or first-seen time; the consensus is the latest manual (then Nasdaq, converted per share via `ads_ratio` and FX) snapshot dated before the release.
  3. `compare`: annual → surprise %; interim (YTD) → completion of the full-year consensus and extrapolation by the last 3 years' seasonal share, only when that share is stable (≥ 2 years, max − min ≤ `NORM_SPREAD`; cyclicals get completion + historical range, no implied gap); loss/near-zero consensus → differences only; flags for few estimates, stale consensus, unstable seasonality, basis differences.
  4. Results go to `earnings` and become an `items` row (kind `data`, source `consensus`, listing = pricing listing, snippet starts with `[程序计算]`) that flows through triage (rule 11; code forces `duplicate_of=""` and `relevant` for these), monitor, tracker evidence and the brief. Tool `earnings_vs_consensus` (dossier, tracker, chat) and `stock consensus show` print current consensus, 30/90-day revisions and the per-period history (A shares recomputed from the library).
- **Tracker** (valuation.py, tracker.py; runs as step 5/6 of `stock run`, after monitor and before the brief):
  1. Baseline (no LLM): `valuation.build_baseline` finds the dossier's `valuation_matrix` tool call that explains the most card scenario endpoints (±1.5%) — using the logged `meta` grid and `basis` when present (the tool records the rows/columns it added), otherwise trying both bases (pre-basis dossiers added net cash to PE matrices too: `ValuationModel.basis` defaults to `ev` so their prices stay as reported, with a flag to re-run), skips calls whose shares disagree with `quote.market_cap / price / 1e8` by >30%, picks each scenario's driver with `choose_drivers` (matrix rows named in the scenario text first, else the largest hit for bull / smallest for bear; then bull ≥ base ≥ bear, flagged when adjusted), and solves each scenario's multiple so its price equals the card range midpoint. No usable matrix → `method="range"` model (drivers are prices, only scalable). Price = `tools.matrix_price` (same function as the matrix tool), clamped at 0; target = probability-weighted (`tracker.target`). fx is recomputed in code from `133.HKDCNH` / `133.USDCNH` bars; the report currency is inferred by matching the matrix fx against those rates.
  2. Candidates: items triaged after (baseline dossier − 2 h) and published ≤ 30 days before it, materiality ≥ `tracker.min_materiality`, not yet in `tracker_refs`; trigger status escalations vs the last revision's snapshot; documents and manual data added after the dossier. No candidates → no LLM call.
  3. Stage A: `run_agent("tracker")` with a `ToolBox(allow=...)` whitelist (web_search removed while the dossier lock is held). Context = valuation model, tracking card (thesis, kill criteria, catalysts, watch metrics, data gaps, related tickers), the dossier's valuation/scenario/insight sections, recent revisions.
  4. Stage B: `complete("tracker")` returns changes as `{path, op: set|add|mul, operand, reason, evidence[], derivation}`; code applies them (`apply_changes`). Rejected: invalid path/op, no valid evidence code, out-of-bounds values, fact paths (`g.shares`, `g.net_cash`, `set` on drivers) whose operand is not found in cited evidence or tool results. Fact-path moves > `tracker.flag_change` are not applied but stored as `confirm: true` entries for the user (`tracker.confirm_change`, WebUI 「采纳」). Methodology issues go to `questions` → flags. No `validate=` hook on this call (one bad change must not fail the whole revision).
  5. Materiality ≥ `tracker.redo_materiality` judged material, or thesis broken → `queue_redo` inserts a `dossier` job (cooldown `redo_cooldown_days`); `cmd_dossier` re-baselines tracked companies after saving the new dossier. `dossier.previous_revisions()` feeds revisions since the last dossier into the next one.
- **Matrix basis**: `valuation_matrix` takes `basis` = `equity` (PE/PB/PS: price = multiple × driver ÷ shares × fx, net cash ignored) or `ev` (EV multiples: net cash added); omitted → `tools.infer_basis(multiple_label)` (contains EV → ev). The pre-2026-10-04 tool always added net cash, which double-counted net debt for PE (cosco: ~4 HKD per scenario).
- **Program anchor** (anchor.py, no LLM; A / HK / US pricing listings — for US ADS the reference price is EPS per share × `ads_ratio` × PE percentile, and `augment` skips the consensus-profit row because the matrix share basis is ambiguous): reference price = consensus EPS (A shares: Eastmoney aggregate `a_consensus` + research-library median; HK: manual / Nasdaq snapshots) × pricing listing's own PE(TTM) percentiles (`tools.valuation_series`, ≤5 years) × fx; next FY is the primary year. `anchor.get` caches per process/day. Used by: the valuation research prompt and the writer's snapshot note (`anchor.text`), `valuation_matrix` auto-adding consensus-profit rows and PE-percentile columns (`anchor.augment`, only when the matrix fx matches the EPS currency), `card["anchor"]` + `card["stats"]["anchor"]` (`anchor.check`, ⚠ beyond `tracker.anchor_band`), `ValuationModel.anchor` (carried into tracker revisions; `tracker.status()["anchor_check"]`, revision page, brief, tracker prompt via `describe`). It never changes prices, targets or stance.
- **Stance check** (valuation.py, no LLM): `risk_stats(model, price)` = weighted upside, base-case upside, probability of ending below the price (uniform within each scenario range, scaled to the current scenario price) and up/down ratio; `reference_stance` applies the same definition the card and tracker prompts use (bullish: upside ≥ +`tracker.stance_band` and P(below) < 50%; bearish: upside ≤ −band, or base below price and P(below) > 50%; else neutral); `stance_check` flags a mismatch with ⚠ and explains tail-driven means. Stats go on the card (`card.stats`), in `describe(model, mode, price, stance)`, `tracker.status`, the company/revision pages (`_stance_stats.html`) and the brief. The stance itself is never changed by code.
- **Kill-criterion direction**: `KillCriterion.direction` is `down` (worse than the thesis) or `up` (better); actions `review|reduce|exit` for down, `review|upgrade` for up (normalised by the validator). `dossier.falsifies(stance, direction)` — bullish is falsified by down, bearish by up, neutral by either; same-direction triggers are 「印证」. Monitor/alert/brief wording comes from `dossier.trigger_label`; tracker evidence and the card context label each K code 「方向·证伪/印证」, and `broken` means a falsifying trigger. Old rows default to `down`.

  - **Per-listing views** (`valuation.listing_views`, no network): every listing of a company gets its own price, target, scenario prices and code-derived stance. The pricing listing uses the model as is; other listings are converted at same-share FX parity (ADS × `ads_ratio`; no FX or ratio → price only, 「无法折算」), so an AH / ADS premium shows up as different upside and stance per listing. `tracker.status()["views"]` (tracked) and `tracker.card_views` (untracked: card scenario midpoints as a range model) feed `views.watch_rows`, which the dashboard and the 观察清单 share: pinned first (kv `pinned:<company id>`), then `view_sort_key` (stance bullish→bearish, upside, up/down ratio; best listing per company); one `tbody[data-group]` per company, one row per listing, filters in `app.js` (`[data-filter-bar]`, market / stance / tracked / pinned / text; company-level cells carry `.grp` and only the first visible row shows them). **String contracts between modules.** Keep these prefixes if you edit the messages:
- Tool errors start with `错误`; the Anthropic agent loop marks those results `is_error`.
- A `web_search` result starting with `没有可用的搜索结果` counts as a search outage (`web.search_failed`), which makes a later `--reuse-notes` rerun gap-fill.
- Failed research notes start with `FAILED_MARK`.
- ima item snippets start with `[原文已入库：资料 #<doc id>]` when the original was stored; `ima_search` refs are `I<n>` (per ToolBox).
- Paper-fund pushes: title prefix `【模拟基金】`, body ends with `fund.report.DISCLAIMER` (「模拟组合信号，非投资建议…」); tests match these.
- Consensus items: source `consensus`, snippet prefix `[程序计算]` (`consensus.TAG`); triage keeps them (never a duplicate). Kill-criterion messages: 「证伪条件触发（向上/向下）」 or 「风险/利好条件触发（与…判断同向，属印证）」 (`dossier.trigger_label`); tests match these strings.
- Tracker evidence codes shown to the model: events `id=<short_id>` (12 hex chars, in the user message so the mock can echo them), kill criteria `K<id>`, documents `D<id>`, manual data `M<id>`, catalysts `C<n>`, stage-A tool results `T<n>`. `tracker_refs.ref` prefixes: `item:`, `trig:<id>:<status>`, `doc:`, `man:<id>:<imported_at>`, `cat:<dossier>:<hash>`. Only the Stage B `events` array uses an `id` field (the mock expands arrays with an `id` property per hex id).

## Rules that are easy to break

- **No shell or generic exec tool for agents.** The research agent reads untrusted web pages, so injected text must never be able to run commands. New capabilities go in tools.py as fixed `Tool`s. External CLIs (mcporter → Exa) are called with a fixed argv, never through a shell. `fetch_text` refuses loopback/private hosts, and `calculate` only evaluates a whitelisted subset of Python syntax (`safe_calc`).
- **Numbers come from code or tools, not the model.** Technicals, AH premium, price reactions, EV/FCF yield (`fcf_snapshot`) and valuation maths are all computed in Python, and prompts demand cited, tool-sourced figures. `ref/价值投资新经济-投资思路蒸馏.md` is the user's valuation framework (EV, FCF yield, Negative EV, SOTP), which `fcf_yield` implements.
- **Stay model-agnostic.** Model-specific knobs (`max_tokens`, `max_input_chars`, `tool_mode`, `json_mode`, `fallback`) belong in `config.yaml` profiles and are uncapped by default. Don't hardcode limits or tailor prompts or code to one model.
- **One `stock dossier` process at a time.** Its 4 parallel agents already exhaust the free search sources (360 captchas last 30+ min) and the local LLM gateway's account pool. `cmd_dossier` enforces this with the `dossier` file lock (a second one exits with a message); `pgrep` misses jobs started as `python -m stockagent.jobrun`, so check `stock web`'s 状态 page or the lock instead.
- **Target prices come from code.** The tracker model never states a new price: it proposes op/operand changes with evidence codes; code validates provenance and recomputes. Keep the scenario-weighted-valuation label and disclaimer wherever a target price is shown.
- **WebUI safety.** Bind only 127.0.0.1; keep TrustedHost, the Origin check and the CSRF dependency on every router; sanitize any LLM/web-derived markdown with `render.md_html` (nh3) and links with `safe_url`; serve stored report HTML with the sandbox CSP; pages must not call networked helpers (`ensure_bars`, `latest_quote`, US `resolve_ticker`).
- **Tests stay offline.** conftest's autouse fixture disables mcporter/Exa and stubs `emdata.fcf_data`, `emdata.financials`, `emdata.research_reports`, `emdata.a_consensus`, `emdata.a_forecasts`, `emdata.a_express`, `emdata.valuation_history_a`, `ccass.holdings`, `sec.company_facts` and `nasdaq._get`. Use the `app` fixture (temp dir, mock LLM), and monkeypatch any network call a new test reaches. To prove a run is offline: `HTTP_PROXY=http://127.0.0.1:9 HTTPS_PROXY=http://127.0.0.1:9 NO_PROXY=127.0.0.1,localhost uv run pytest -q` (the LLM HTTP tests use local servers).
